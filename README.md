## Доставка закрытых электронных работ · 5 ноября 2026

После входа ученика следующая native-версия в фоне обходит сохранённые `.history` его штатных персональных копий, включая контексты прежних занятий. Открывать каждую схему не нужно; доставка работает и на экране SQL. Снимок/отчёты передаются с прежними ClientId/UUID, история — с прежним контекстом занятия. Перед открытием редактора фоновая запись отменяется и освобождает файлы.

Повреждённая/отсутствующая очередь, чужой контекст или изменившаяся привязка показываются как требующие восстановления: исходники не переименовываются и случайная новая копия не создаётся. Автоматическая доставка старых очередей без `.history`, интерфейс восстановления электронных файлов, архивы и полная приёмка ещё впереди. Схема БД в этом шаге не меняется; рабочая установка не заменена.

## Локальная пошаговая история электроники · 5 ноября 2026

Следующая native-версия сохраняет правки кода и промежуточные состояния движений/поворотов/размеров деталей в локальную историю ученика. Undo/Redo, события окна, запуск и намерение сдачи имеют отдельные отметки; UUID отчёта связан с хешем отправленного снимка. Завершённые блоки истории неизменяемы. Переносить нужно обычную схему, очередь `.sync.json` и всю соседнюю папку `.history`.

Если обычный файл схемы отстаёт или повреждён, открывается проверенная версия этого занятия из истории, а несовпадающий файл сохраняется отдельно. Повреждённая история не заменяется пустой. **Доставка электронной истории преподавателю и её просмотр ещё разрабатываются**; прежние снимки запусков/сдач продолжают работать. Серверная миграция в этом шаге не нужна, установленная версия не заменена.

Устранена обнаруженная при общем прогоне гонка служебного файла компилятора: параллельный поиск оставшихся ресурсов больше не мешает атомарной записи; краткая Windows-блокировка допускает ограниченный повтор. Изоляция AppContainer сохраняется.

## Действия и точные попытки в SQL-истории · 5 ноября 2026

В следующей native-версии история различает Undo/Redo, сброс запроса, запрос/открытие подсказки, переходы в работу/справочник и события окна. Запуск, повтор и получение результата связаны с исходной операцией. Из шага можно открыть подтверждённую попытку с отправленным SQL, точной ошибкой и сохранённой исходной базой, затем вернуться к выбранному шагу. Неподтверждённое намерение не выдаётся за выполненный запрос; переключение окна не считается доказательством списывания.

Новая миграция — `SqlJournalExecutionLinks`; прежние попытки без номера операции не связываются догадками. Teacher/Server и Student обновляются совместно. Рабочая установка не заменена; история электроники, архивы, новая статистика и полная приёмка остаются в плане.

Восстановленный текст повторно сверяется с черновиком преподавателя; при расхождении предлагается выбор. Если проверенной копии нет, исходный файл остаётся без замены.

## Локальное сохранение SQL · 5 ноября 2026

В следующей версии SQL-код сохраняется на диске ученика сразу при изменении. Отдельно для каждого сервера, профиля, занятия и работы хранятся черновик, неподтверждённый запрос с прежним UUID и очередь событий. После входа доставка продолжается, в том числе когда открыт другой предмет. Подтверждённый старый запрос можно сверить с квитанцией без его выполнения в новой паре.

При разных черновиках на двух компьютерах приложение показывает оба текста и предлагает выбор; оба сохраняются на ПК. Ошибка локальной записи не выдаётся за успешное сохранение. Teacher/Server и Student обновляются совместно: старый сервер не поддерживает новые маршруты доставки. Рабочая установленная версия пока не заменена; полная пошаговая история и остальные пункты плана ещё разрабатываются.

## Изолированная компиляция электроники · 5 ноября 2026

В ветке следующей версии Arduino-код компилируется в отдельном Windows AppContainer: чтение публичного комплекта, запись в собственную временную папку, без сетевых возможностей и наследования среды приложения. Отмена/лимит завершают всё дерево процессов; после аварийного выхода следующий запуск очищает принадлежащие ему временные профили и пути. При ошибке защиты обычный незащищённый запуск не используется.

Для сборки автономного комплекта теперь нужны Visual Studio C++ x64 Build Tools на сборочном ПК. Скрипт `avalonia/scripts/prepare-electronics.ps1` подготавливает GCC AVR 16.1.0 и x64 Arduino ctags из закреплённого исходника; на компьютерах класса Build Tools и интернет не требуются. Копировать нужно весь комплект, включая `sandbox-avr` и `offline-ready-v3.json`. Детали и границы проверок — в [архитектуре Avalonia](avalonia/docs/architecture.md). Рабочая установленная версия не заменена; Windows 10/LAN и полная совместимость Cirkit ещё требуют приёмки.

## Точная проверочная копия SQL-попытки · 5 ноября 2026

В истории SQL преподаватель открывает попытку с закреплёнными условием, редакцией, кодом и первоначальным результатом. Для новых запусков сохраняется исходное состояние учебной базы. SQL можно изменить и выполнить отдельно; каждый проверочный запуск начинает с базы выбранной попытки и не меняет работу или статистику ученика.

Старые попытки без сохранённого состояния доступны для просмотра с явной пометкой: точное воспроизведение недоступно. Текущая проектная база вместо прежней не подставляется. Миграция `SqlExecutionEvidence` сохраняет существующие данные; обновлять Server и SQL worker нужно вместе. Работа находится в ветке разработки, установленная версия пока не заменена.

## Проверочная копия и одноразовый доступ · 4 ноября 2026

Из очереди схем можно открыть и запустить сданную версию в отдельной временной копии, изменить её для проверки и восстановить исходный снимок. Эти запуски не добавляют попыток ученику. Его черновик, сдача и собственная схема преподавателя сохраняются отдельно.

«Код проверки у ученика» выдаёт код на 5 минут. На ученическом ПК «Проверка преподавателя» открывает ожидающие работы этого ученика на 15 минут; доступны просмотр/запуск копии и оценка. Доступ связан с текущим сеансом ученика, отзывается преподавателем и не открывает управление группами/настройками. После завершения возвращается прежняя работа, общая пауза продолжает действовать.

Это часть E09. Отдельная проверочная SQL-среда ещё впереди; полнота симуляции Cirkit, изоляция компилятора средствами ОС и окончательная приёмка не подтверждены этим шагом. Новая миграция БД не нужна; Teacher/Server и Student обновляются совместно.

## Проверка схем и оценки · 4 ноября 2026

В кабинете постоянно доступна «Проверка схем» со счётчиком. Очередь включает назначенные и прежние свободные сдачи; преподаватель видит именно отправленную схему/код, выставляет результат, комментарий и оценку 1–5. Исправление оценки добавляет запись в историю. Возврат назначенной работы на доработку либо «Разрешить пересдачу» открывает следующую сдачу, сохраняя предыдущую.

Ученик получает результат в своей работе. Очередь хранит версию разрешения вместе с намерением отправки: старый запрос после обрыва связи не становится новой пересдачей автоматически. Для замены такой отправки ученик явно подтверждает новую сдачу; исходное намерение остаётся в локальном архиве.

Очередь фильтруется по группе и занятию. Это часть E08: запуск сданной копии и одноразовая проверка у ученика — E09; политика пересдач свободных проектов ещё требует доработки. Рабочая установленная версия пока не заменялась. Требуется совместное обновление Teacher/Server и Student; новая EF-миграция — `ElectronicsReviews`.

Выданная редакция сохраняется независимо от последующих изменений каталога; каждый ученик получает свою работу. Без начальной схемы открывается пустая схема.

Ученик видит электронные работы в «Моё занятие», переключается между ними с сохранением кода/схемы и отправляет неизменяемую версию на проверку. Появляется «Ожидает проверки», повторная сдача закрывается до разрешения преподавателя. Очередь преподавателя, выставление оценок и разрешение пересдачи реализуются в E08/E09; текущий шаг ещё не даёт полный процесс оценивания. Импорт Cirkit и компоновка кода под схемой остаются отдельной работой.

## Повторное решение SQL · 4 ноября 2026

При выдаче преподаватель выбирает «Зачесть прежнее» или «Новое решение». Для проекта режим применяется ко всей цепочке. Работа пары хранит собственные черновик, подсказки, проверки, ответ и SQL-снимок проекта; прошлый решённый результат курса не перезаписывается. После первого открытия учениками режим нельзя менять на этой паре.

Если выдача изменилась во время практики, прежний черновик сохраняется в своём контексте, ученик возвращается в «Моё занятие» и открывает новую работу отдельно. Запросы связаны с занятием и контекстом работы. Подробная история правок, надёжная локальная SQL-очередь, электронные задания и новая сводная статистика остаются следующими этапами.

## Свободное преобразование деталей · 23 октября 2026

## Варианты заданий

- Первые два вводных упражнения общие. Для остальных 118 предусмотрены четыре версии: основная и три альтернативы.
- При входе по коду группы и псевдониму версия закрепляется в D1. Четыре последовательно зарегистрированных ученика группы получают разные номера для одного задания; пятый повторяет один из четырёх.
- Альтернативы используют отдельные имена таблиц, изменённые числовые данные, а некоторые задачи — другие условия. Это автоматически подготовленные версии одной учебной цели, не четыре независимо написанных упражнения.
- Все шаги одного проекта используют одну версию базы. Выданные задания сохраняются целиком: обновление каталога не меняет работу уже зарегистрированного ученика.
- Гости работают с общей основной версией. Для разных вариантов ученики должны войти в группу.

Варианты затрудняют прямое копирование ответа, но не заменяют контрольную систему: ученик может адаптировать запрос или посмотреть клиентский код. Вход «код + имя» также не подтверждает личность.


Для существующей базы применяйте только отсутствующие миграции. Не запускайте старые повторно и не удаляйте базу ради обновления. `db:generate` нужен при изменении схемы, а не при обычном запуске.

Для входа преподавателя создайте локальный `.dev.vars` с `ADMIN_PASSWORD_HASH=<SHA-256 выбранного пароля>`. Файл игнорируется Git. На опубликованном сайте одноимённый секрет задаётся отдельно в Sites. Вход расположен в меню шестерёнки.

## Проверка изменений

```sh
pnpm exec tsc --noEmit
pnpm check:variants
pnpm build
```

Проверка вариантов выполняет 480 эталонных решений, последовательные проекты, перенос гостевой базы и отклонение неизменённых чужих ответов для самостоятельных упражнений. Дополнительно вручную проверяйте затронутые экран, вход, сохранение и мобильную навигацию.

## Совместная работа

Исходники передаются через GitHub; у каждого участника свой локальный проект и чат с помощником. История чата не синхронизируется с кодом. Перед началом работы получите актуальную ветку, затем создайте отдельную ветку для своей задачи и отправляйте изменения через pull request. Не используйте принудительную отправку общей ветки.

На текущем Windows-ПК `origin` указывает на `TISHKEREFPEK/sql-trainer` в GitHub. В прежнем окружении Sites имена remote отличались; на каждом компьютере сначала смотрите `git remote -v`, не полагайтесь на старые названия.

**Отправка кода в GitHub не обновляет размещённый сайт.** Публикация Sites и миграция серверной D1 выполняются отдельно после проверки. Для этой версии перед публикацией необходима миграция `0003` (и ранее отсутствующие миграции).

### Подсказки desktop

В локальной desktop-переработке открытия подсказок сохраняются в профиле ученика и отображаются в статистике преподавателя. Повторный вход восстанавливает открытые тексты. Требуется будущая сборка обновлённых приложений; существующие установщики не изменены.

### Оформление desktop

В локальной переработке есть шесть тем и настройка собственных цветов. Кнопка Оформление доступна после входа; тема сохраняется в профиле ученика или преподавателя. Текущие Windows-установщики требуют будущей пересборки для получения этой возможности.

### Личные пресеты оформления

В локальной desktop-версии можно сохранить до 30 собственных тем с названиями, выбрать их в «Мои темы» и удалить. Пресеты сохраняются сразу, независимо от отмены смены активной темы. Они привязаны к профилю ученика или преподавателя и восстанавливаются при входе. Новые установщики и публикация не выполнялись.
