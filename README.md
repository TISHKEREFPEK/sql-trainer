# SQL-пространство

Русскоязычный тренажёр SQLite с нуля: **120 заданий**, короткий курс, практика на наборах данных и три последовательных проекта — библиотека, магазин, запись на занятия.

Сначала ученик читает задание, затем объяснение и пример. В карточке есть раскрываемые таблицы с данными, краткие определения и две подсказки. Подробный словарь находится в «Повторении». При ошибке показаны точный ответ SQLite и пояснение на русском. Таймера в интерфейсе ученика нет.

## Варианты заданий

- Первые два вводных упражнения общие. Для остальных 118 предусмотрены четыре версии: основная и три альтернативы.
- При входе по коду группы и псевдониму версия закрепляется в D1. Четыре последовательно зарегистрированных ученика группы получают разные номера для одного задания; пятый повторяет один из четырёх.
- Альтернативы используют отдельные имена таблиц, изменённые числовые данные, а некоторые задачи — другие условия. Это автоматически подготовленные версии одной учебной цели, не четыре независимо написанных упражнения.
- Все шаги одного проекта используют одну версию базы. Выданные задания сохраняются целиком: обновление каталога не меняет работу уже зарегистрированного ученика.
- Гости работают с общей основной версией. Для разных вариантов ученики должны войти в группу.

Варианты затрудняют прямое копирование ответа, но не заменяют контрольную систему: ученик может адаптировать запрос или посмотреть клиентский код. Вход «код + имя» также не подтверждает личность.

## Версия для компьютерного класса

Ветка **codex/desktop** развивается отдельно от сайта на main. В desktop/ находится прототип приложений преподавателя и ученика. Инструкция запуска, сборки Windows и ограничения — в [desktop/README.md](desktop/README.md). Первый тест обеих ролей выполнен в Windows 11/Parallels; найден сбой восстановления SQL-черновика. Локальная правка разделяет browser sessions ролей, но ещё требует новой Windows-сборки. Это пока тест на одном компьютере; сеть класса и TLS ещё не реализованы. Отправка этой ветки не обновляет Sites.

## Быстрый старт

Нужны Node.js ≥22.13 и pnpm 11. Команды выполняются в корне **этого репозитория**, где находится `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm build
```

На новой локальной базе примените миграции по порядку:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_ambitious_kylun.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_teacher_tasks.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_task_variants_analytics.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_learner_variant_assignments.sql
pnpm dev
```

Для существующей базы применяйте только отсутствующие миграции. Не запускайте старые повторно и не удаляйте базу ради обновления. `db:generate` нужен при изменении схемы, а не при обычном запуске.

Для входа преподавателя создайте локальный `.dev.vars` с `ADMIN_PASSWORD_HASH=<SHA-256 выбранного пароля>`. Файл игнорируется Git. На опубликованном сайте одноимённый секрет задаётся отдельно в Sites. Вход расположен в меню шестерёнки.

## Проверка изменений

```sh
pnpm exec tsc --noEmit
pnpm check:variants
pnpm build
```

Проверка вариантов выполняет 480 эталонных решений, последовательные проекты, перенос гостевой базы и отклонение неизменённых чужих ответов для самостоятельных упражнений. Дополнительно вручную проверяйте затронутые экран, вход, сохранение и мобильную навигацию.

## Совместная работа

Исходники передаются через GitHub; у каждого участника свой локальный проект и чат с помощником. История чата не синхронизируется с кодом. Перед началом работы получите актуальную ветку, затем создайте отдельную ветку для своей задачи и отправляйте изменения через pull request. Не используйте принудительную отправку общей ветки.

В этом checkout `github` — репозиторий команды, `origin` — исходный репозиторий Sites. В свежем клоне с GitHub обычно единственный remote `origin` указывает на GitHub: сначала смотрите `git remote -v`.

**Отправка кода в GitHub не обновляет размещённый сайт.** Публикация Sites и миграция серверной D1 выполняются отдельно после проверки. Для этой версии перед публикацией необходима миграция `0003` (и ранее отсутствующие миграции).
