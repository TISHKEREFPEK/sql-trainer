# SQL Classroom · Avalonia

Два самостоятельных приложения Windows x64: **Преподаватель** и **Ученик**. Учебные данные, профили и проверка SQL находятся на компьютере преподавателя. Клиенты работают через HTTPS в локальной сети без интернета.

## Сборка

Версии закреплены в `global.json`, файлах проектов и `packages.lock.json`: .NET SDK 10.0.401 / runtime 10.0.12, Avalonia 11.3.22, AvaloniaEdit 11.4.1, CommunityToolkit.Mvvm 8.4.0, EF Core / SQLite 10.0.12. DataGrid 11.3.13 совместим с Avalonia 11. Native SQLite bundle 2.1.13 закреплён отдельно.

На Windows установите SDK из `global.json`, PowerShell и Inno Setup 6, затем выполните:

```powershell
./avalonia/scripts/build-windows.ps1
```

Скрипт выполняет locked restore, Release build, тесты и четыре self-contained публикации, проверяет отсутствие серверных файлов в ученической поставке и создаёт два установщика в `avalonia/artifacts/installers`. Установленный .NET, Node.js и Electron для работы не нужны. `-SkipInstaller` создаёт папки приложений, `-SkipTests` пропускает проверки при повторной упаковке.

GitHub Actions `.github/workflows/avalonia-windows.yml` выполняет эту сборку на Windows; результаты находятся в артефакте `SQL-Avalonia-Windows-x64`. Установщики пока без цифровой подписи. Установщик и удаление приложения сохраняют пользовательские базы и настройки вне каталога программы.

## Запуск из исходников

```powershell
cd avalonia
dotnet restore Classroom.sln --locked-mode
dotnet build Classroom.sln
dotnet run --project src/Classroom.Teacher --no-build
# В другом терминале:
dotnet run --project src/Classroom.Student --no-build
```

Сервер и worker должны быть собраны вместе с решением. Роль определена отдельным исполняемым файлом. После входа преподавателя можно создавать ученические логины и группы. Минимум пароля преподавателя — 10 символов, ученика — 8. Ученическая поставка содержит только UI, сетевой клиент и контракты; серверные Domain/Storage/Worker и каталог эталонов в неё не входят.

Для изолированного локального запуска можно установить `CLASSROOM_DATA` на отдельную папку. Переменная влияет только на данные преподавателя. Если `dotnet` не находится в PATH, `CLASSROOM_DOTNET` указывает на его исполняемый файл.

## Сеть кабинета

1. Установите приложение преподавателя на его компьютер. Первый запуск использует loopback `127.0.0.1:47831` и создаёт сертификат.
2. В **Настройки → Подключение учеников** укажите IP сетевого интерфейса преподавателя, доступного в кабинете, и порт. Завершите приложение через **Завершить работу** и запустите снова.
3. В Windows Firewall разрешите входящие TCP-подключения на выбранный порт для частной сети кабинета. Адрес и правила определяются при установке.
4. Передайте ученикам показанный HTTPS-адрес и полный SHA-256 отпечаток. Они сверяют его с экраном преподавателя и вводят при подключении.
5. Введите отдельный ученический логин и пароль. Отпечаток сохраняется локально; другой сертификат отвергается. При смене сертификата требуется повторное сопряжение.

При закрытии окна преподавателя на Windows приложение уходит в область уведомлений, сервер продолжает занятие. **Завершить работу** останавливает сервер после текущих запросов. Повторный запуск с той же базой блокируется. После перезапуска сервера ученики входят снова; несохранённые черновики и незавершённые операции остаются в памяти открытого окна. После закрытия окна при потере связи несохранённый текст утрачен — приложение предупреждает об этом.

## Данные, импорт и копии

Данные преподавателя: `%LOCALAPPDATA%\SQL-Classroom\teacher`; сопряжение ученика: `%LOCALAPPDATA%\SQL-Classroom\student`. Основная база `classroom.sqlite`, сертификат `server.pfx`, настройки `server-settings.json`, копии в `backups`. Эти файлы не входят в Git и поставку.

В **Настройки → Перенос из Electron** выберите копию прежней `classroom.sqlite`. Сначала показывается состав, затем выполняется транзакционный импорт. Сохраняются профили, Node scrypt-хеши и действующие ученические пароли, выданные задания и редакции, прогресс, проектные базы, попытки, открытые подсказки, темы и пресеты, преподавательские изменения и ограничения. Уже настроенный пароль нового преподавателя сохраняется. Повтор того же файла не создаёт дубликаты; конфликтующие профили отменяют импорт. Исходник читается без изменений.

Локальная копия тестовой базы Electron импортирована в игнорируемую `avalonia/.classroom-data`: 1 ученик, 1 назначение, 1 попытка; хеш пароля и прогресс совпали, источник не изменился. Для запуска с этими данными установите `CLASSROOM_DATA` на эту папку.

Если в Electron нет отдельной даты завершения, она восстанавливается из сохранённой успешной попытки, а при её отсутствии — датой импорта. Число проверок и ошибок восстанавливается по имеющемуся журналу (Electron ограничивал его последними 1000 событиями). Данные, которых Electron не сохранял, не выдумываются.

Для первоначального импорта до создания нового преподавателя:

```powershell
$env:CLASSROOM_DATA = "$PWD/.classroom-data"
dotnet run --project src/Classroom.Server -- --import-electron "C:/backup/classroom.sqlite" --import-only
```

При этом переносится и старый scrypt-хеш преподавателя. Не используйте работающую базу другого процесса как источник; выберите её копию.

Копии создаются ежедневно, перед миграцией схемы, импортом и восстановлением, а также вручную из настроек. Восстановление проверяет SQLite и таблицы Classroom, сохраняет текущую базу и требует повторного входа. Импорт и восстановление недоступны во время активных проверок. Сетевые параметры и сертификат не заменяются восстановлением учебной базы; при переносе компьютера сохраните их отдельно.

## Проверки и готовность

```powershell
cd avalonia
dotnet test Classroom.sln -c Release
```

Проверяются соответствие TypeScript-вариантам, все эталонные решения и проектные цепочки, SQLite-ошибки и ограничения, scrypt, атомарность импорта, сохранение и повторные операции, роли, HTTPS pinning, перезапуск сервера, 35 одновременных клиентов и headless-отрисовка экранов. Проверка сети использует настоящий дочерний сервер и настоящие рабочие процессы, а не подмену API.

Снимки UI сохраняются в `artifacts/ui` при установке `CLASSROOM_UI_OUTPUT`; тесты не записывают персональные данные. Проверка учебного каталога использует синтетические профили.

**Приёмка в кабинете остаётся отдельной:** два физических компьютера, Windows 11 и используемая Windows 10, реальные масштаб/DPI/клавиатура, обновление поверх прежней установки, сворачивание в tray, ограничение прав/памяти worker и захват окна. Локальные проверки на macOS и CI не заменяют эти пункты. Защита `SetWindowDisplayAffinity` исключает окно из поддерживаемого захвата Windows и не обнаруживает все снимки экрана.
