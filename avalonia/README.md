## Сегменты истории SQL, формат кэша v3 · 5 ноября 2026

Каждые завершённые 64 изменения записываются в `p-<SHA256>.json` рядом с Work-файлом. Текущий `.work.json` хранит индекс и до 63 последних изменений; завершённые блоки не переписываются на каждой клавише. Файлы v1/v2 читаются и при сохранении переходят к v3. Копировать нужно всю папку профиля, а не один `.work.json`: backup и архивы могут ссылаться на прежние сегменты. Автоматической очистки сегментов пока нет, чтобы не удалить необходимую историю. Повреждённый/пропавший сегмент вызывает ошибку восстановления, без тихого усечения. Установленные приложения не заменялись.

## Локальный журнал SQL, первый шаг E07 · 5 ноября 2026

SqlLocalWork сохраняет начальный текст и изменения с UUID, порядком, временем часов клиента, происхождением и хешами до/после. Изменения редактора записываются без debounce; копия полного текста добавляется каждые 64 шага. Конфликтный выбор/получение серверного текста и восстановление backup также сохраняют переход. При открытии журнал проверяется полным проигрыванием. Кэш без истории v1 читается, при записи журнала становится v2; откат приложения не должен молча стирать журнал. Отдельные метки команд Undo/Redo пока не реализованы, но их текстовые результаты записываются.

Пока журнал внутри общего атомарного файла: для длинных занятий ещё требуется сегментация/оптимизация записей. При превышении квоты ошибка явная, история не обрезается. Серверная доставка/ACK, просмотр преподавателем, действия вне текста, журнал схем и политика архивов остаются E07. На установленную рабочую версию изменение не накатывалось.

## Восстановление SQL-кэша · 5 ноября 2026

При повреждённом `.work.json` экран восстановления показывает код из проверенного `.backup`. Нажатие «Восстановить предыдущую копию» сохраняет повреждённый оригинал в соседнем `.damaged-<GUID>`, оставляет backup и восстанавливает работу атомарно. Изменившиеся после просмотра или принадлежащие другому профилю файлы не принимаются. Восстановленный код считается ожидающим сверки с сервером, поэтому более новый черновик у преподавателя не подменяется молча. Pending SQL сохраняет UUID; восстановление не запускает его автоматически. Без подходящей копии новая пустая работа не создаётся. После восстановления нужен обычный вход.

## SQL-черновики и очередь на диске · 5 ноября 2026

`%LOCALAPPDATA%/SQL-Classroom/student/sql` хранит учебные данные отдельно по отпечатку сервера и ID ученика, затем по занятию/контексту/заданию. `CLASSROOM_STUDENT_DATA` меняет корень для изолированных стендов. Сохраняются доступное ученику описание задания, код, незавершённый ExecuteRequest с исходным UUID и события. Пароли, bearer/review-токены и преподавательские решения не записываются. Файлы JSON имеют версию и контрольную сумму, атомарную замену с flush и предыдущую `.backup`; повреждённый файл не перезаписывается стартовым шаблоном. Одновременная запись другого окна того же профиля блокируется файловой блокировкой.

Статусы различают сохранение на ПК, ожидание доставки и подтверждение преподавателя. При расхождении серверного и локального черновиков открывается сравнение/выбор с сохранением обоих вариантов. Запрос с неизвестным результатом сохраняет исходный UUID/код; сверка квитанции не выполняет SQL. Явно отклонённые сервером запросы остаются в локальном архиве и не заставляют повторять отвергнутый код. Старые занятия принимают лишь сохранение уже существующей работы своего участника, без права запуска.

Первичный вход по-прежнему требует связи с преподавателем и допуска на занятие; локальный кэш не является обходом входа. Это часть E06: полная история/просмотр архивов, расширенная проверка восстановления, настройки хранения, Windows 10/LAN и остальные пункты плана остаются открытыми. Миграция БД не нужна, но Teacher/Server и Student требуется обновлять вместе.

## Рабочее поле электроники · 5 ноября 2026

Согласованная компоновка «код под схемой» подключена к обычному редактору и проверочной копии. Кнопки «Детали», «Свойства», «Код и монитор» открывают/скрывают панели; подпись открытой панели предлагает её скрыть. Граница между схемой и кодом перетаскивается и сохраняет выбранные размеры при сворачивании кода в этом редакторе. На узком окне детали и свойства открываются по очереди, освобождая место схеме. Инструкции по коду раскрываются отдельно и не заменяют пользовательскую программу. Монитор — соседняя вкладка нижней панели. Прежние результаты преподавателя остаются доступны отдельно от рабочей области.

Это изменение интерфейса, не формата проекта: JSON, назначения, сдачи и код не мигрируются. Положение камеры сохраняет центр при смене размеров. Кнопки контактов платы имеют минимальную область 12 px после вписывания в уменьшенное поле; макетная плата сохраняет отдельные отверстия. Полнота симуляции/графики/Cirkit, журнал и ограничения отмеченных электронных заданий остаются отдельными открытыми пунктами.

## Автономный компилятор с изоляцией · 5 ноября 2026

`prepare-electronics.ps1` подготавливает комплект v3: Arduino CLI 1.5.1, ядро AVR 1.8.6/Servo 1.2.2, GCC AVR 16.1.0 x64 и Arduino ctags из исходника `abc8fca7499f44c725122881cd380a88c37abe0e`, собранного в x64. На сборочном Windows-ПК нужны Visual Studio C++ x64 Build Tools (обнаруживаются через vswhere), .NET SDK и интернет для первой подготовки. Уже подготовленный комплект используется без интернета и Build Tools. `prepare-sandbox-compiler.ps1 -RuntimePath <папка>` отдельно подготавливает новую часть; обе скачиваемые ZIP проверяются SHA-256. Исходник/лицензия ctags включаются в комплект, источники AVR указаны в manifest; окончательная проверка состава исходников и лицензий перед распространением остаётся в E14.

Компиляция использует AppContainer с собственным scratch и чтением публичного toolchain; лимиты 60 секунд, 16 процессов, 768 МиБ на процесс и 2 ГиБ на дерево, не более двух компиляций приложения одновременно. Вывод ограничен; отмена и закрытие host завершают дочерние процессы. Нет перехода к запуску без изоляции. Старая Win32-сборка GCC 7.3/ctags без таблицы relocations на этом стенде не запускалась в контейнере (Windows 623), поэтому оставлена для прежней версии, а новая использует отдельный `sandbox-avr`.

Кэш публичного комплекта: `%LOCALAPPDATA%/SQL-Classroom/compiler-runtime`; журнал временных ресурсов: `compiler-leases` рядом с ним. При следующей компиляции очищаются ресурсы завершившихся host-процессов; чужие буквы дисков не заменяются. Для изолированных тестов доступны `CLASSROOM_COMPILER_CACHE`, `CLASSROOM_COMPILER_LEASES`, `CLASSROOM_TEST_SANDBOX_PROBE`; тестовый Probe намеренно аварийно завершает только себя. На текущем Windows 11 проверены реальные компиляции/симуляция и запреты; Windows 10 пока не проверена.

## Исходные состояния SQL-попыток · 5 ноября 2026

Новые проверки и непустые запуски SQL фиксируют редакцию задания, код, результат/ошибку и состояние базы до выполнения. Одинаковые состояния переиспользуются в пределах ученика; удаление профиля удаляет и эти снимки. Повтор UUID операции не создаёт ещё одну попытку или снимок. После обновления каталога и дальнейших шагов проекта выбранная попытка остаётся связана со своей исходной базой.

В истории SQL «Открыть попытку SQL» показывает исходный результат и отдельный редактор проверки. Каждый запуск использует изолированный SQLite worker с той же базой/правилами задания; данные ученика не обновляются, проверочные действия не добавляют ему попыток и прогресса. Остановка отменяет запрос; действуют прежние очередь/лимиты worker. Для прежних попыток без исходного снимка запуск закрыт с объяснением; старая редакция и вывод не выдумываются.

Миграция `20261104222327_SqlExecutionEvidence` добавляет данные, не изменяя прежние строки. **Server и SQL worker обновлять вместе:** CaptureState/EvidenceVersion защищают от незаметного запуска с прежним worker. Проверочные маршруты требуют обычный teacher-доступ; одноразовый доступ к ожидающим схемам не расширяется до SQL или управления кабинетами. Новая объединённая статистика/навигация E10, полный журнал E07 и изоляция компилятора электроники средствами ОС остаются открытыми.

## Запуск сданной схемы и проверка у ученика · 4 ноября 2026

В очереди «Открыть и запустить копию» загружает неизменяемый ProjectJson сдачи в новый временный каталог. Редактор не имеет ученического API/outbox: компиляция и запуск не записывают его учебную статистику. Можно восстановить точную сданную версию; возврат сохраняет форму оценивания. Уход с экрана останавливает запуск, закрытие удаляет временную копию.

Преподаватель выдаёт и при необходимости отзывает одноразовый код для выбранного ученика. Код действует 5 минут; новый код завершает прежнюю проверку этого ученика. Ученический экран «Проверка преподавателя» принимает код и даёт 15-минутный допуск к ожидающим работам только текущего ученика/сеанса входа. SQL, группы, каталог, настройки и чужие ученики этим допуском не открываются. Пять неверных кодов ограничивают повтор на минуту. Завершение, отзыв, выход преподавателя, восстановление базы и перезапуск закрывают допуск.

Проверка доступна при общей паузе и возвращает тот же несданный черновик; до обновления политики исходный рабочий экран блокируется. Секрет временного доступа не сохраняется в ученических настройках или проекте. При обрыве связи проверочная копия закрывается; отзыв при локальном выходе отправляется с пределом 2 секунды, серверный срок остаётся обязательным при недоступной сети. Модель БД не менялась. Это ещё не полный E09: проверочная SQL-среда и проверенная изоляция native-компилятора средствами ОС остаются открытыми.

## Очередь и ручная оценка схем · 4 ноября 2026

«Проверка схем» доступна над меню преподавателя и в результатах. Отображаются неизменяемые сдачи с условием, ФИО, группой, датой, статусом и оценкой. Преподаватель выбирает «Принято», «На доработку» либо «Не принято»; принятию/отказу нужна оценка 1–5, возврату можно оставить её пустой. Комментарий — до 8000 символов. Все решения и разрешения пересдачи сохраняются последовательно; редактирование результата не заменяет прежний.

Состояние назначенной работы и разрешение новой сдачи меняются только при проверке её последней сдачи. Пересмотр старой версии не меняет состояние новой. Ученик видит последний результат, комментарий и дату, сохраняет собственный черновик. Старые свободные отчёты доступны для оценки отдельно; общий процесс пересдачи свободного редактора остаётся открытым. Запуск снимка и одноразовый доступ — E09.

Миграция `20261104192442_ElectronicsReviews` добавляет историю решений и ожидаемую версию отправки; старые отчёты читаются. Обновлять сервер и клиент вместе. ## Свободное преобразование деталей · 23 октября 2026

Выбранная деталь выделяется синей рамкой по её повернутым границам. Четыре угловых маркера меняют ширину и высоту независимо, круглый маркер вращает на любой угол. Курсор размера учитывает направление угла; курсор вращения — рука. Shift сохраняет пропорции при растяжении и задаёт шаг 15° при вращении, Escape отменяет текущий жест. Один жест — один шаг отмены; точки подключения, провода, просмотр работ преподавателем и SVG используют то же преобразование.

JSON v1 расширен необязательными Angle=0, StretchX=1 и StretchY=1; старые Scale, QuarterTurns и зеркальный Rotation сохраняют поведение. Растяжение ограничено 0.1–10 по каждой оси, угол нормализован в [0,360). Сервер и проверка резервных копий принимают и проверяют новые поля без изменения таблиц или миграции. Цвет рамки задаётся в свойствах как #RRGGBB и сохраняется локально рядом со схемой в .selection-color; он не входит в ученическую работу. Обновлять Teacher/Server и Student вместе. Электрические параметры от преобразования не меняются.

Минимум пароля преподавателя — 10 символов, ученика — 8. Ученическая поставка содержит только UI, сетевой клиент и контракты; серверные Domain/Storage/Worker и каталог эталонов в неё не входят.

В редакторе преподавателя флажок запрета буфера и захвата окна действует на выбранное задание, включая уже открытое у ученика после очередного опроса. Для применения нажмите **Сохранить**; это работает в основной и альтернативных версиях. В остальных заданиях копирование разрешено. Windows-защита исключает главное ученическое окно из поддерживаемого захвата; если ОС откажет, приложение показывает ошибку. Обнаружение каждого снимка и блокировка внешней фотографии не обещаются.

Текущий режим постоянно показан над SQL-редактором. При попытке Ctrl+C/X/V появляется немедленное пояснение, а при серверной блокировке — причина паузы. Если флажок не сохранён, явно показано, что ограничения не включены. Win+Shift+S может открыть системный инструмент захвата; запрет относится к содержимому ученического окна в результате снимка. Всплытие предупреждения на каждое системное сочетание не гарантируется: оно может не поступить приложению.

Созданная группа сразу выбирается в форме нового ученика. Список обновляется и при фоновом опросе, сохраняя текущий выбор.

Для изолированного локального запуска можно установить `CLASSROOM_DATA` на отдельную папку. Переменная влияет только на данные преподавателя. Если `dotnet` не находится в PATH, `CLASSROOM_DOTNET` указывает на его исполняемый файл.

## Сеть кабинета

1. Установите приложение преподавателя на его компьютер. Первый запуск использует loopback `127.0.0.1:47831` и создаёт сертификат.
2. В **Настройки → Подключение учеников → Параметры сети** укажите `0.0.0.0` (все IPv4-интерфейсы) либо IP компьютера преподавателя в кабинете и порт. Завершите приложение через **Завершить работу** и запустите снова. При `127.0.0.1` код работает только на одном компьютере.
3. При настройке сети разрешите входящие TCP-подключения на выбранный HTTPS-порт и UDP 47832 для частной сети кабинета. Обнаружение использует multicast `239.255.47.83`; Wi-Fi с изоляцией клиентов/VPN/запрет multicast могут помешать поиску. Проверка на двух физических ПК остаётся отдельной приёмкой.
4. Войдите в профиль преподавателя и нажмите **Код подключения** в углу. Откроется встроенная страница с кодом и кнопкой **Назад к SQL**. В SQL-вкладках её нет, автоматически при входе она не показывается. До входа и после выхода код скрыт; отдельное окно не открывается. Ученик вводит три группы по четыре символа и нажимает **Подключиться**. Регистр и дефисы необязательны. Адрес и сертификат подставляются автоматически; вводить их ученику не нужно.
5. Затем ученик вводит свой логин и пароль. Код не заменяет пароль. HTTPS проверяет полный отпечаток сертификата. После перезапуска преподавателя код меняется; при неверном коде или недоступной сети поиск завершается понятным сообщением и допускает повтор.

Переход на стенд, выбранный преподавателем, пока не включён: подготовлены только контракт и место будущей маршрутизации после входа. Сейчас открывается обычный учебный экран. Код работает в локальной IPv4-сети без интернета, публичного сервиса поиска нет. Старые опубликованные установщики нужно пересобрать для нового интерфейса.

При закрытии окна преподавателя на Windows приложение уходит в область уведомлений, сервер продолжает занятие. **Завершить работу** останавливает сервер после текущих запросов. Повторный запуск с той же базой блокируется. После перезапуска сервера ученики входят снова; несохранённые черновики и незавершённые операции остаются в памяти открытого окна. После закрытия окна при потере связи несохранённый текст утрачен — приложение предупреждает об этом.

## Данные, импорт и копии

Данные преподавателя: `%LOCALAPPDATA%\SQL-Classroom\teacher`; сопряжение ученика: `%LOCALAPPDATA%\SQL-Classroom\student`. Основная база `classroom.sqlite`, сертификат `server.pfx`, настройки `server-settings.json`, копии в `backups`. Эти файлы не входят в Git и поставку.

В **Настройки → Перенос из Electron** выберите копию прежней `classroom.sqlite`. Сначала показывается состав, затем выполняется транзакционный импорт. Сохраняются профили, Node scrypt-хеши и действующие ученические пароли, выданные задания и редакции, прогресс, проектные базы, попытки, открытые подсказки, темы и пресеты, преподавательские изменения и ограничения. Уже настроенный пароль нового преподавателя сохраняется. Повтор того же файла не создаёт дубликаты; конфликтующие профили отменяют импорт. Исходник читается без изменений.

Локальная копия тестовой базы Electron импортирована в игнорируемую `avalonia/.classroom-data`: 1 ученик, 1 назначение, 1 попытка; хеш пароля и прогресс совпали, источник не изменился. Для запуска с этими данными установите `CLASSROOM_DATA` на эту папку.

Если в Electron нет отдельной даты завершения, она восстанавливается из сохранённой успешной попытки, а при её отсутствии — датой импорта. Число проверок и ошибок восстанавливается по имеющемуся журналу (Electron ограничивал его последними 1000 событиями). Данные, которых Electron не сохранял, не выдумываются.

Для первоначального импорта до создания нового преподавателя:

```powershell
$env:CLASSROOM_DATA = "$PWD/.classroom-data"
dotnet run --project src/Classroom.Server -- --import-electron "C:/backup/classroom.sqlite" --import-only
```

При этом переносится и старый scrypt-хеш преподавателя. Не используйте работающую базу другого процесса как источник; выберите её копию.

Копии создаются ежедневно, перед миграцией схемы, импортом и восстановлением, а также вручную из настроек. Восстановление проверяет SQLite и таблицы Classroom, применяет отсутствующие миграции, сохраняет текущую базу и требует повторного входа. Импорт и восстановление недоступны во время активных проверок. Сетевые параметры и сертификат не заменяются восстановлением учебной базы; при переносе компьютера сохраните их отдельно.

Отчёты включают сводки группы, сложные задания, места остановки и историю завершений. Проверка сети использует настоящий дочерний сервер и настоящие рабочие процессы, а не подмену API.

## Демонстрация статистики

Для локального просмотра создайте **новую отдельную** папку данных. Генератор отказывается работать с существующими профилями или назначениями; обычный запуск никогда не добавляет демоданные. Синтетические даты/результаты служат демонстрации, не являются результатами реальных учеников.

После сборки Release, из каталога avalonia:

```powershell
$env:CLASSROOM_DATA = Join-Path $PWD '.classroom-data/demo-statistics'
New-Item -ItemType Directory -Path $env:CLASSROOM_DATA -Force | Out-Null
Set-Content -LiteralPath (Join-Path $env:CLASSROOM_DATA 'server-settings.json') -Value '{"address":"127.0.0.1","port":47833}'
$env:CLASSROOM_SERVER = Join-Path $PWD 'src/Classroom.Server/bin/Release/net10.0/Classroom.Server.dll'
$env:CLASSROOM_WORKER = Join-Path $PWD 'src/Classroom.Worker/bin/Release/net10.0/Classroom.Worker.dll'
dotnet $env:CLASSROOM_SERVER --seed-demo
$env:CLASSROOM_DEMO = '1'
$env:CLASSROOM_STUDENT_DATA = Join-Path $env:CLASSROOM_DATA 'student-settings'
dotnet run --project src/Classroom.Teacher -c Release --no-build
```

Случайные пароли сохраняются локально в demo-access.json выбранной папки. Не публикуйте этот файл. Вход выполняется обычной формой. Демоокна помечены «Демонстрация», преподаватель после входа открывает статистику. Для ученика запустите Student с теми же переменными окружения и введите код с экрана преподавателя; отдельный CLASSROOM_STUDENT_DATA сохраняет его сопряжение независимо от рабочего.

В демо есть 20 учеников, три наполненные группы, пустая группа, ученики без группы/без активности, разные варианты, ошибки, подсказки, нарушения и старый ответ без сохранённого SQL. У demo-01 в первом задании история длиннее 100 событий, принятый ответ отличается от черновика.

Статистика обновляется при открытии вкладки и кнопкой «Обновить», сохраняя выбранный уровень. Время событий записывает сервер, отображается зона компьютера преподавателя. Активное время — оценка взаимодействия: активное окно, нет блокировки и не более двух минут без клавиш/нажатий/прокрутки. Часы ученику не показываются. Исторические данные до новой миграции не восстанавливаются догадками. Событие снимка фиксируется только если клавиша поступила приложению; полное число снимков неизвестно.

## Проверка сохранённой базы

Остановите сервер выбранной базы либо используйте отдельную копию/backup. Задайте CLASSROOM_DATA на эту папку и выполните после сборки:

```powershell
dotnet src/Classroom.Server/bin/Release/net10.0/Classroom.Server.dll --check-database
```

Команда выполняет обычную инициализацию (включая копию перед отсутствующими миграциями), затем проверяет integrity_check, foreign_key_check, таблицы, JSON заданий/профилей/операций, подсказки и проектные снимки. Сервер HTTPS не запускается. Результаты ученических SQL при этом не исполняются в основной базе. На работающей базе действует защита второго экземпляра.

Восстановление из настроек проверяет и мигрирует временную копию до замены рабочей базы, отвергает неизвестные версии/неполную схему/нарушенные связи и сохраняет исходный backup. SQLite backup переносит проверенную базу транзакционно, без ручного удаления WAL. Лимит seed редактора — 2 млн символов, включая все встроенные большие наборы.

[Результаты проверки 20 октября](docs/functionality-audit-2026-10-20.md). Штатный каталог и варианты не менялись; проверка учебной программы остаётся отложенной.

Новая пустая схема содержит только пустые setup() и loop(); пример Blink сохраняет собственную программу. Добавление компонента не вставляет код автоматически.
