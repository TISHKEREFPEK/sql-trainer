# Архитектура Avalonia Classroom

## ElectronicsScreen: схема над кодом · 5 ноября 2026

`ElectronicsScreen.Workspace` объединяет прежние workGrid/codePage/monitor без создания нового проекта/редактора: GridSplitter между сценой и нижним TabControl. Меняются только ширины/видимость панелей и размеры строк; код, выделение и камера принадлежат прежнему экземпляру. Размеры разделителя сохраняются при скрытии/возврате кода, обновление свойств не сбрасывает их. При выборе элемента открываются свойства; при ширине поля менее 1100 px они и библиотека открываются по очереди. Дальнейшее обновление выбранной детали не раскрывает закрытую панель повторно. CircuitViewport сохраняет центр камеры при SizeChanged. Вся библиотека находится в одном ScrollViewer с обрезкой по панели, чтобы её заголовки/фильтры не выходили поверх кода при малой высоте сцены.

В ученическом/свободном/проверочном редакторе схема всегда над кодом; нижние вкладки — код и serial. Если прежний teacher-editor имеет ElectronicsResultsView, внешний TabControl отделяет результаты от всей рабочей области и сохраняет остановку/сохранение при уходе к результатам. Конструктор/Dispose и синхронизация назначений остаются прежними. Код-гайд закрыт по умолчанию, генерация по-прежнему явная с подтверждением. Состояние панелей локально экземпляру экрана и не добавляется в JSON сдачи. Контакты, кроме отверстий breadboard, центрируются на исходных координатах с минимумом 12 px, чтобы default-fit меньшего поля не сделал Pico недоступным для нажатия.

Новая компоновка не закрывает E06/E07: долговечная SQL-очередь/конфликты, весь журнал, электронные ограничения и другие оставшиеся пункты плана ещё открыты. Полнота плат/компонентов/симуляции и достоверная графика не меняются этим шагом; native/DPI на целевом Windows 10 ещё требуют приёмки.

## Windows AppContainer для компиляции · 5 ноября 2026

`CompilerRuntime` готовит отдельный кэш только из `arduino-cli.exe`, публичных индексов, `data/packages`, `user/libraries`, `sandbox-avr`. Входные reparse points отклоняются; SHA-256 имени кэша вычисляется из версии формата, путей, размеров/дат файлов. Это ключ обновления, не проверка подлинности содержимого; скачиваемые архивы проверяет подготовительный скрипт. Подготовка сериализована семафором и межпроцессным file lock. Возможность `sqlClassroomCompilerRuntimeRead` получает RX на копию комплекта, не на исходные каталоги пользователя. Только уникальный package SID получает Modify на scratch с low integrity; соседние работы не получают этот SID.

`WindowsSandboxProcess` создаёт обычный AppContainer без сетевых capabilities, с одной пользовательской возможностью чтения toolchain. Явный HandleList содержит лишь NUL/stdout/stderr, среда не наследуется: Windows/PATH, временный профиль и разрешённые `ARDUINO_*` пути. Уникальные временные буквы дисков позволяют инструментам канонизировать пути без разрешения чтения `C:\Users`; существующие mappings не заменяются, удаление использует exact target. `CompilerLease` перед созданием mappings пишет журнал с GUID, PID и start time host; после сбоя следующий запуск проверяет владельца и очищает только записанные mappings/профиль с собственным GUID. Журнал не передаётся контейнеру.

До Resume процесс включается в job с KillOnClose, запретом breakaway, 16 процессами, 768 МиБ на процесс и 2 ГиБ суммарно. По завершении основной команды, отмене или 60-секундному лимиту завершается всё дерево; перед сбором вывода ожидается его остановка. По 128000 символов на поток с пометкой сокращения, до 8000 символов ошибки пользователю. Одновременно приложение допускает две компиляции. Любая ошибка включения защиты прекращает запуск, не включает fallback. Симуляция AVR8js остаётся отдельным существующим runner; изменение не доказывает полноту моделей/плат или общий аудит Node runner.

Комплект v3 включает GCC AVR 16.1.0 x64 и x64-сборку неизменённого Arduino ctags `abc8fca7499f44c725122881cd380a88c37abe0e`. Старые Win32 GCC 7.3/ctags на стенде имели stripped relocations и не запускались в AppContainer с Windows 623; байтовое исправление PE не применяется. Новый ctags строится исходным `mk_mvc.mak` через VS C++ x64 Build Tools, только target `ctags`. Два предупреждения GNU regex относятся к передаче целочисленного индекса через void pointer; исходник не правился, полная эквивалентность парсера одним тестом не доказывается. Реальные Arduino-прототипы, Servo и Serial проверяются тестами. Manifest, ctags source ZIP/COPYING и vendor-файлы входят в комплект; финальный аудит соответствующих исходников/лицензий остаётся E14.

Подтверждено на Windows 11: компиляция работает, приватные include/incbin не читаются, parent/child не меняют runtime и чужие файлы, loopback недоступен, отмена убивает потомков, аварийный host exit закрывает job и оставляет восстанавливаемые ресурсы. Windows 10 и полный offline package/LAN пока не подтверждены. Приложения/данные рабочей установки не заменены.

## Точное SQL-состояние попытки · 5 ноября 2026

SqlEngine.CaptureState экспортирует actual до SQL. Ответ содержит EvidenceVersion=1; WorkerRunner проверяет его при запросе захвата, чтобы старый бинарник не выдавал неполную историю незаметно. При обычной ошибке возвращаются и BeforeSnapshot, и точные Error/Explanation. При прерывании без захваченного состояния сервер использует только уже известный исходный проектный снимок, либо явно оставляет его отсутствующим.

В транзакции результата сохраняются Attempt, Operation и SqlExecutionEvidence с TaskJson/редакцией из начала исполнения, Check и оригинальным ExecutionDto. BeforeHash ссылается на SqlExecutionStates (StudentId/hash), содержащий канонический Base64; SHA-256 вычисляется по SQLite-байтам. Повтор запроса не дублирует записи, идентичные состояния ученика переиспользуются. Каскады профиля сохраняют удаление всех его данных; health проверяет связи/хеши/SQLite/форму результата. Миграция `20261104222327_SqlExecutionEvidence` добавлена отдельно, прежние строки не меняются.

SqlReviewRoutes требует teacher-role и запускает только worker с замороженными TaskJson/BeforeState. Клиент передаёт SQL, не собственную базу. Каждый запуск начинается с того же before-state; текущее состояние проекта ученика и общая metadata SQLite не участвуют. Проверка не вызывает автоматическое оценивание и не меняет попытки/прогресс/счётчики ученика. RequestAborted передаётся в штатный worker с ограничениями очереди, времени, памяти и SQL authorizer. Нативная страница показывает отдельные исходный/проверочный результаты, ошибки SQLite без потери текста, восстановление исходного ответа и остановку.

История прежней версии не содержит этих before-state. API/интерфейс явно отмечают legacy/missing-state и не разрешают точное воспроизведение без состояния; редакция/вывод для legacy остаются неизвестными. Полный журнал и интеграция новых результатов E07/E10 продолжаются. Для E09 также остаётся строгая файловая изоляция native-компилятора электроники. Изменений D1 нет.

## Сданная копия и одноразовая проверка · 4 ноября 2026

`ElectronicsReviewWorkspace` запускает обычный ElectronicsScreen из точного JSON сдачи в новом temp-каталоге. У него нет ClassroomApi или ElectronicsSync; события запуска не относятся к статистике ученика. Reset пересоздаёт копию из исходного снимка, возврат возвращает прежнюю форму, скрытие останавливает симуляцию, Dispose удаляет проверенный собственный temp-путь. Действуют прежние лимиты runtime, но отдельная проверочная SQL-среда и строгие права файлов для native-компилятора ещё не реализованы/не подтверждены.

`ReviewAccessRegistry` в Domain имеет TimeProvider для доказательства сроков в тестах. Хранит хеши: код из 12 случайных цифр на 5 минут, 256-битный допуск на 15 минут. Выдача кода для ученика отзывает его прежние коды/допуски; 5 неверных вводов блокируют повтор на минуту. Redemption требует действующий student-сеанс и живой teacher-сеанс, фиксирует конкретный сеанс входа ученика. Параллельное погашение выдаёт ровно один допуск. Истечение, отзыв, явное завершение, выход инициатора, очистка после restore и перезапуск прекращают действие.

Нормальный Authorization остаётся student; независимый клиент добавляет X-Review-Token только в памяти. Ограниченные маршруты `/review-access` повторно проверяют область/срок перед работой под Gate и используют общий сервис решений. В очереди только ожидающие отчёты цели; уже открытая сдача остаётся доступной для подтверждения результата. Ни один обычный teacher-маршрут не использует этот заголовок. Коды/токены/проверочные JSON не попадают в конфигурацию ученического профиля.

`StudentReviewPage` закрывает копию при утрате связи/допуска; локальный выход сразу убирает интерфейс и посылает ограниченный по времени отзыв. При недоступном сервере срок/сеансы всё равно ограничивают оставшийся допуск. Основной экран сохраняется за страницей, действия проверки не проходят ученические перехватчики. Общая пауза не блокирует режим проверки; возврат восстанавливает ту же работу, временно закрывает редактирование до очередной политики и восстанавливает защиту захвата SQL. EF-модель и D1 не менялись.

## Очередь ручной проверки · 4 ноября 2026

`ElectronicsReviews` хранит последовательные решения и отдельные разрешения пересдачи для StudentId/ReportId. UUID операции и хеш запроса обеспечивают безопасный повтор; ExpectedReviewId и ExpectedAssignmentVersion отклоняют запоздалое решение. Коррекция добавляет строку, не меняет прошлую оценку. Результат по последней назначенной сдаче меняет State/CanSubmit/StateVersion; проверка более старой версии влияет только на её историю.

Очередь `/teacher/reviews/electronics` содержит только метаданные, глобальное число ожидающих и страницы по 30, принимает status/groupId/lessonId. Отдельный detail возвращает неизменённый ProjectJson сдачи, закреплённое условие и историю. Нативная `ElectronicsReviewQueueView` показывает фильтры группы/занятия, просмотр и форму; постоянно доступная кнопка TeacherScreen опрашивает счётчик и уведомляет о новых сдачах без удаления их из очереди. Начальный старый список не создаёт уведомлений. Старые свободные сдачи также оцениваются; единой политики разрешённой пересдачи свободного редактора пока нет.

Ученик читает только собственную сдачу/решения; маленький `/status` содержит последнее решение без JSON проекта. ExpectedAssignmentVersion фиксируется при постановке submitted в локальную очередь и входит в серверный отчёт. Старое намерение не использует позднейшее разрешение. При явной новой отправке устаревшее намерение сохраняется в `.superseded-*.json`, не меняет свой UUID/версию. ACK сохранённого отчёта остаётся идемпотентным после оценивания.

Миграция `20261104192442_ElectronicsReviews` и health-проверка добавлены отдельно от прежних миграций; SQLite/D1 учебного сайта не менялись. Проверочная копия с запуском и ограниченный одноразовый режим у ученика остаются E09. HostManager и синтетический старт теперь повторяют чтение объявления при временной блокировке/неполном JSON; наличие файла само по себе ещё не означает готовность сервера.

## Электронные задания и контексты · 4 ноября 2026

`ElectronicsAssignments` добавляет ElectronicsTasks, ElectronicsTaskRevisions, LessonElectronicsTasks и ElectronicsAssignments. В выдаче сохранены название/условие/необязательный JSON схемы с кодом, редакция и дата; отзыв не удаляет снимок. Редактирование каталога не заменяет выдачу. Assignment имеет уникальный ключ занятие/ученик/задание, собственный начальный JSON и состояние. При отсутствии шаблона создаётся пустой проект, не демонстрационная Blink.

CRUD каталога защищён teacher-ролью, ожидаемая редакция предотвращает потерю правок; история доступна `/teacher/electronics/tasks/{id}/revisions`. Удаление из каталога мягкое, прежние выдачи/работы доступны. `/teacher/lessons/{id}/electronics-tasks` сохраняет выбор. `/electronics/tasks/{id}` проверяет разрешённое направление/выдачу и создаёт персональную работу. Повтор открытия возвращает тот же ID; другой ученик получает другой контекст. `/electronics/assignments/{id}` читает только собственную работу, `/status` опрашивает состояние без передачи большого JSON.

ElectronicsWorks/ElectronicsReports имеют nullable AssignmentId: старые свободные копии не переименовываются. Sync проверяет владельца и неизменность привязки ClientId; квота 10 устройств применяется на назначение отдельно. Для накопленной передачи назначенного задания проверяются владение и участие в исходном занятии; конец пары не теряет очередь. JSON отчёта остаётся неизменяемым. Первый новый submitted переводит Assignment в awaiting-review, CanSubmit=false и увеличивает StateVersion. Повтор того же UUID подтверждается без новой сдачи, другая сдача до разрешения отклоняется.

MainWindow кеширует отдельные ElectronicsScreen по AssignmentId и свободный экземпляр. Файл/sidecar включают отпечаток сервера, профиль и AssignmentId; новый экземпляр получает начальную/последнюю серверную копию, существующая локальная схема не заменяется опросом. Опрос обновляет только доступность/статус, запоздавшая меньшая StateVersion игнорируется. Локальная очередь сохраняет AssignmentId и не дублирует ещё ожидающую передачи сдачу. После ACK интерфейс показывает «Ожидает проверки». Длинное условие прокручивается в ограниченной области, сохраняя место редактору.

Границы: очередь проверки преподавателя, оценки/комментарии/возврат и разрешение пересдачи ещё E08/E09. StateVersion станет основанием для проверки ожидаемой версии при пересдаче; не отправлять старую заблокированную очередь автоматически как новую пересдачу после будущего разрешения. Полная история правок — E07. Restricted сохранён в модели, но его электронный UI/перехват команд ещё E06, авторинг флаг не предлагает. Код под схемой, импорт/симуляторы Cirkit и остальные этапы также не закрыты.

## Контексты SQL и повторная выдача · 4 ноября 2026

Миграция `20261104174346_LessonSqlWorkspaces` добавляет RequireNewSolution в выдачу, LessonSqlWorks (PK занятие/ученик/задание), LessonSqlSnapshots (занятие/ученик/проект), LessonId/WorkScope SQL-событий. Работа хранит собственные JSON/редакцию, черновик, подсказки, счётчики/даты, зачтённый код и ссылку на исходную выдачу; прошлые условие/ответ/дата сохранены отдельно. CreatedAt — создание контекста (для проекта вся цепочка), StartedAt — известное начало взаимодействия. Не выдавать создание соседнего шага за его просмотр.

`ISqlWork` объединяет доступ к прежней работе курса и новой работе пары. `LessonSqlWorkspaces` создаёт совместимую цепочку, выбирает целую прошлую редакцию/её базу для зачёта либо начинает чистое решение из снимка выдачи. Проект не собирается из шагов разных прошлых контекстов. Среди завершённых прошлых вариантов выбирается последний правильный результат по дате завершения; поздняя неверная практика не подменяет его. Уже решённые ответ и база курса не перезаписываются. Первое решение той же ещё не решённой редакции может отметить её завершение в курсе, без замены иного старого JSON/черновика.

`LessonSqlSelectionRequest.RequireNewTaskIds` задаёт новый режим; null сохраняет прежние настройки для старых клиентов. Для проекта режим распространяется на цепочку. После появления ученической работы смена режима возвращает 409, чтобы не обнулить начатое решение. Отзыв работы сохраняет её контекст/снимки. `/teacher/lessons/{lessonId}/students/{studentId}/sql/{taskId}` возвращает текущие и прошлые условие/ответ/даты только преподавателю; статистический UI пока не использует новый API полностью.

LoginDto несёт LessonId, StudentTask — WorkScope (`course` либо `lesson:<id>`). SQL-запросы/черновики/активность/события передают оба значения, квитанции и буферы разделены. Старый запрос исполнения не выполняется в новой паре или в перевыданном контексте. Накопленное сохранение прежней практики в текущей паре записывается в прежнюю работу курса, не в новый черновик. Фоновый GET с ожидаемым WorkScope замечает перевыдачу до создания нового контекста; клиент сохраняет старый черновик, прекращает опрос старого экрана и открывает «Моё занятие». Новая работа открывается явно. Dispose ученического экрана идемпотентен; исправлена повторная очистка CancellationTokenSource.

Границы шага: свободная практика ещё использует прежнюю работу курса; долговечная SQL-очередь с восстановлением/разрешением конфликтов и доставкой в старые занятия — E06, пошаговая история — E07. Общая статистика всё ещё опирается на прежние данные курса: E10 должен объединить новые работы пары и отличать их от курса/практики. Проверка самостоятельных электронных работ, ручное оценивание, код под схемой и полнота Cirkit остаются открытыми. Это не завершение E05/E06 или всей цели.

## SQL-выдача и первый домашний экран · 4 ноября 2026

`20261104165827_LessonSqlTasks` добавляет таблицу с PK LessonId/TaskId, снимком JSON задания, полным набором вариантов, редакцией, порядком/датой выдачи и флагом Withdrawn. Отзыв не удаляет снимок; повторное включение сохраняет редакцию. В рамках пары шаги проекта не смешиваются с новым изданием каталога. Выдача автоматически включает полную цепочку. ## Подключение по коду

PairingCode / PairingAnnouncement (Contracts) — протокол обнаружения версии 1. Сервер при обычном запуске генерирует 32 случайных байта nonce, сохраняет локальный pairing.json и показывает 12 символов кода с разделителями. Код — 60 бит SHA-256 от версии протокола, HTTPS-порта, полного SHA-256 сертификата и nonce; меняется после перезапуска. Это выбор и сверка сервера, не аутентификация ученика. Короткий код даёт меньшую криптографическую стойкость, чем ручная сверка 256 бит; целевая коллизия требует порядка 2^60 попыток.

PairingDiscovery слушает IPv4 multicast 239.255.47.83:47832 на доступных интерфейсах. Отвечает только на запрос своего кода и сообщает порт, fingerprint и nonce; loopback-сервер не отвечает удалённым компьютерам. Несколько преподавателей на одном компьютере могут слушать общий multicast-порт. TeacherDiscovery посылает запрос на активных IPv4-интерфейсах с TTL=1, три раунда, не более семи секунд, игнорирует повреждённые ответы и несовпадающие коды. После проверки кода берёт IP отправителя и открывает обычный ClassroomApi с полным TLS pinning. Пароли и токены в UDP не передаются. Сетевые экраны, изоляция Wi-Fi и запрет multicast могут препятствовать поиску; автоматического интернет-каталога/relay нет. IPv6-only обнаружение пока не поддерживается. Ошибка discovery-сокета не останавливает учебную базу/HTTPS.

HostManager читает код только после успешного старта HTTPS. TeacherScreen создаётся после успешной аутентификации; кнопка в углу открывает отдельную встроенную страницу ConnectionCodeView вместо списка SQL-вкладок. Load не открывает её автоматически. «Назад к SQL» возвращает прежние вкладки; дополнительных Window нет. ShowLogin удаляет TeacherScreen и кнопки, скрывая код до входа и после выхода. Ученик вводит код перед обычной формой логина/пароля. connection.json сохраняется для совместимости локального сопряжения; сохранённая связь не подставляется вместо нового кода. Новых EF/D1-миграций нет.

## Автономные стенды

MainWindow сохраняет SQL-экран и отдельный ElectronicsScreen между переключениями преподавательского списка стендов. При уходе из электроники Suspend останавливает firmware-процесс и атомарно сохраняет CircuitProject; ShowLogin/Quit вызывают Dispose. Полная модель/границы и сборочный runtime описаны в [electronics.md](electronics.md). Drop-down не меняет LoginDto.Destination: передача выбранного стенда ученикам ещё не реализована. Ученик по-прежнему загружает SQL.

Nullable LoginDto.Destination и LessonDestination — только контракт будущего выбранного стенда. Сервер сейчас его не заполняет. MainWindow.EnterLesson — место будущей маршрутизации; сейчас всегда загружает привычный учебный экран, без изменения назначений и прогресса.

## Хранение

Обычные таблицы: Groups, Profiles, Tasks, TaskRevisions, Variants, Assignments, Snapshots, Attempts, Operations, Imports; схема версионируется EF Core. Преподавательские отчёты включают фильтр группы, средний прогресс, ошибки и время по задачам/темам, первое незавершённое задание и историю завершений. Активное время учитывается у незавершённой задачи в активном окне без паузы; ученику часы не показываются.

Сложное содержимое задания сохраняется JSON внутри отдельной строки редакции/назначения. Успешная попытка, CompletedAt, проектный снимок и ответ идемпотентной операции записываются одной SQLite-транзакцией.

TaskRevisions хранит полный авторский текст и подготовленные альтернативы при правке. Assignments независимо сохраняет весь выданный вариант. Изменения и удаление каталога не меняют начатую карточку; каталог ученика показывает его сохранённую редакцию. Все шаги проекта выдаются вместе, с ProjectOrder и одним вариантом. Добавленный позднее шаг получает новый ученик; он не добавляется в старую цепочку молча.

Gate сериализует чтение/изменение основной базы, импорт и восстановление. Сам SQL работает вне Gate, в отдельном worker. На ученика допускается одна операция одновременно; на сервер — четыре worker и очередь 35. При импорте/восстановлении не должно быть активных операций. Профиль выполняющего запрос ученика нельзя удалить до завершения.

Черновики отправляются через 650 мс после изменения, сериализуются на клиенте и восстанавливаются после входа. При обрыве текст остаётся в памяти окна и отправляется после восстановления. После перезапуска сервера новый вход сохраняет локальные изменения и pending operation; состояние в памяти разделено по профилям.

## SQL

Worker получает только задачу, изолированный учебный снимок и SQL, без пути или соединения основной базы. Базы выполнения/эталона — in-memory. SQLite authorizer включается перед seed и отклоняет ATTACH/DETACH, расширения, файловые функции, виртуальные таблицы и небезопасные PRAGMA. Режим query запрещает изменения. Начальные/конечные комментарии допускаются, строковые литералы сохраняются; закомментированный BEGIN/COMMIT не подтверждает транзакцию. Сравниваются столбцы, значения, повторы, порядок при Ordered; для state — строки, колонки, индексы с составом/направлением/collation, foreign keys, views/triggers; для constraint/transaction есть дополнительные проверки.

Проектный снимок создаётся только после верной state-проверки. Обычный запуск использует последнюю подтверждённую базу, не изменяет её и не возвращает файл клиенту. Показ результатов ограничен 200 строками, расчёт — 50 000 строками, таблицы для просмотра — 8 строками на таблицу.

Windows: Job Object ограничивает worker до 256 МБ, одного процесса и завершает дерево при закрытии. Синхронный поток SQLite работает с restricted token без привилегий и с deny-only Administrators SID. Выполнение ограничено пятью секундами после выхода из очереди. На macOS ограничение native-памяти Job Object и restricted token отсутствуют; целевая поставка Windows.

## Протокол

Ученические маршруты: login/logout, catalog/glossary/tasks, hint, draft/activity/violation, execute, theme/theme-presets. Преподавательские: overview, students/password/group/unlock, groups, tasks/variants/revisions, import preview/commit, backups/restore/stop. Проверки ролей серверные; преподавательский вход и первичная настройка доступны только loopback. Browser Origin отклоняется. Bearer-токены хранятся в памяти и живут восемь часов; перезапуск требует нового входа.

Операция execute имеет UUID и хеш неизменяемого запроса. Повтор UUID возвращает сохранённый результат; другой SQL с этим UUID даёт 409. Клиент сохраняет первоначальные code/check/UUID до получения ответа. Подсказка имеет последовательный индекс; повтор не меняет время открытия.

Сертификат RSA 3072 создаётся на первом запуске, сохраняется в пользовательской папке и закрепляется SHA-256 на каждом ученическом компьютере. Не используется глобальное принятие любых TLS-сертификатов. Смена адреса не требует смены сертификата; новый сертификат требует ручной сверки. Срок сертификата пять лет, его автоматическое обновление не входит в V1.

Ограничение — общая политика задания независимо от его версии. Необязательное `SaveVariantRequest.Restricted` сохраняет политику и вариант одним `SaveChanges`; отсутствие поля сохраняет старую политику для совместимости прежних клиентов. Неизменяемое назначение не мешает обновлению этой политики при опросе.

Клиент блокирует не только KeyDown/Drop, но и Copy/Cut/Paste-команды AvaloniaEdit и clipboard-события стандартных TextBox. За нарушение по-прежнему отвечает отдельный API с серверной паузой и журналом. Windows SetWindowDisplayAffinity проверяется обратным чтением GetWindowDisplayAffinity; отказ ОС виден в статусе. Это защита поддерживаемого захвата главного окна, не регистрация всех снимков. Список групп преподавателя обновляется независимо от обновления списка задач, не пересоздаётся при неизменном составе и сохраняет выбранную группу.

## Учебный источник и расширение

`Domain/Data/catalog.json` экспортирован из текущих `lib/course`, наборов данных и glossary. Авторский `scripts/export-catalog.cjs` использует TypeScript при обновлении исходного каталога; установленным приложениям JavaScript не нужен. Эталонные fixtures фиксируют 120 исходных задач и 354 альтернативы, назначения и hash seed. При правке старого каталога повторно выполните экспорт и проверки обоих движков.

Для новых функций добавляйте серверную политику, отдельный DTO, миграцию без изменения старых файлов, UI и предметную проверку. Расширение сетевого протокола сохраняет `/api/v1`; несовместимые изменения требуют новой версии. Контрольные как сущность, облачная синхронизация, автоматические обновления и платформы кроме Windows не входят в V1.

## Статистика и история работ

Новые поля Assignments/Attempts и миграция LearningHistory описаны также в корневой docs/architecture.md. LearningAnalytics содержит teacher-only метаданные и отдельную загрузку SQL одной работы, LearningStatisticsView — четыре уровня навигации с фильтрами и CSV. В знаменатель прогресса входят доступные ученику задания с сохранением его исторической проектной цепочки; среднее группы включает нулевой прогресс. Трудности ранжируются по доле ещё не решивших среди проверявших, с количеством участников и пометкой малой выборки (<5).

StartedAt — первое явное открытие нового задания; периодический GET не меняет даты активности. LastActivityAt обновляется при открытии, сохранении черновика, подсказке, SQL или событии ограничения. AcceptedCode и ActiveSecondsAtCompletion фиксируются только при первом успехе вместе с CompletedAt и проектным снимком. Attempts хранит SQL проверки/непустого запуска, результат и пояснение; подсказки сохраняют прежние идемпотентные timestamps. Старые пустые поля остаются неизвестными. Даты сервера выводятся в локальной зоне преподавателя, активная длительность отдельно; таймер ученику не добавлен.

Идемпотентные events хранят квитанцию в Operations; activity использует одну монотонную последовательность на экземпляр StudentScreen, учитывает серверный elapsed и исключает заблокированные/завершённые назначения. Серверные timestamps и elapsed ограничивают случайные повторы, но клиентская активность не является доказательством внимания или средством аттестации. Транспортная очередь событий остаётся в памяти открытого окна.

DemoData запускается только флагом --seed-demo и только при пустых Profiles/Assignments. Генерирует синтетическую историю и случайные локальные учётные данные, без изменения рабочего каталога/базы. CLASSROOM_DEMO маркирует окна; CLASSROOM_STUDENT_DATA изолирует сопряжение ученика. Контрольные как сущность и изменения сайта/D1 этим этапом не вводятся.

## Исправления надёжности 20 октября

DatabaseHealth и подготовленный stage используются при restore; в исходной копии не меняются миграции или данные. Проверенный stage переносится SQLite BackupDatabase после before-restore. --check-database использует обычную инициализацию и те же проверки содержимого, завершая процесс до запуска HTTPS.

StudentScreen стартует polling до preview, не посылает preview на паузе или одновременно с Execute, сохраняет pending только для неопределённых/повторяемых ошибок. Кнопки запуска/проверки восстанавливаются через актуальную политику, а не безусловное true в finally. JSON API отвергает отсутствующие обязательные поля и null. Каталожный seed допускает до 2 млн символов; сортировка дат/длительностей использует timestamps/секунды. Оба CSV обнуляют выходной поток перед записью.

Новая пустая схема содержит только пустые setup() и loop(); пример Blink сохраняет собственную программу. Добавление компонента не вставляет код автоматически.
