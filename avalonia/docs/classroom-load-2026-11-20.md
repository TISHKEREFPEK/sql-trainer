# Нагрузка на сервер занятия · 20 ноября 2026

Два последовательных прогона Release на основном ПК разработки с Windows 11 Pro x64 (10.0.26200), AMD Ryzen 7 5800X3D (8 ядер, 16 потоков), 31,9 ГиБ ОЗУ и .NET SDK 10.0.401. Тест запускал отдельный процесс Classroom.Server по HTTPS на `127.0.0.1` с временной SQLite-базой и штатными процессами SQL Worker. Клиенты использовали `ClassroomApi` с одного ПК.

В каждом прогоне 35 синтетических учеников из двух групп (18 и 17) входили на одно занятие, сохраняли черновики и отправляли 3 521 событие истории SQL. Затем 35 SQL-проверок и 12 сценариев сдачи схем стартовали одновременно. Схемы дали ещё 922 события истории. Повторная доставка SQL-проверок, первых пакетов SQL-истории и сдач схем сохранила исходные результаты без дублей. Преподаватель в это время запрашивал сводку, занятие, каталог схем, ленту активности и очередь проверки с паузой 250 мс между циклами. В приложении опрос идёт раз в пять секунд.

Сценарий подтвердил 35 зачётов с одной проверкой на ученика, 12 уникальных сдач, совпадение сданного снимка с журналом, одну оценку 5 и 11 работ в очереди. Все 35 клиентов увидели паузу и возобновление. После штатного перезапуска преподаватель явно восстановил занятие, один ученик вошёл повторно. Тест вновь сверил состав групп, зачёты, очередь, оценку, один архивный SQL-ответ и конечные состояния каждого из 35 SQL-журналов и 12 журналов схем.

Оба прогона прошли без ошибок запросов. Базовый серверный сценарий на 35 SQL-клиентов тоже прошёл. Время смешанной нагрузки составило 3,24 с в каждом прогоне. Сам сервер использовал 3,22 и 3,92 процессорной секунды за это окно. Пиковый рабочий набор с момента запуска составил 399,4 и 409,8 МиБ. Замеры ресурсов охватывают процесс Classroom.Server. Дочерние SQL Worker и процесс тестов измеряются отдельно при приёмке. Задержка SQL измерена от вызова клиентского API до ответа, вместе с ожиданием на сервере, запуском Worker и исполнением. Пик из 35 запросов в исходных прогонах зафиксирован со стороны клиентов. Для шести циклов преподавателя p95 совпадает с максимумом и описывает лишь этот прогон.

## Диагностика очереди

После добавления серверной диагностики смешанный сценарий прошёл ещё два раза на том же ПК. В обоих прогонах сервер допустил 35 запросов, принял до 31 запроса в очередь при четырёх занятых исполнителях и не отказал ни одному клиенту. P95 ожидания исполнителя составил 1 359,9 и 1 357,9 мс, максимальное ожидание — 1 361,1 и 1 359,0 мс. P95 полного SQL-запроса со стороны клиента — 1 609,5 и 1 610,1 мс. Повторная отправка тех же операций не занимала исполнителей. Проверены отказ в диагностике без входа и для ученика, освобождение всех исполнителей после прогона и обнуление метрик после перезапуска. Сборка Release и 42 проверки `Classroom.Tests` также прошли.

Снимок доступен через `ClassroomApi.Get<SqlWorkerDiagnostics>("teacher/diagnostics/sql-worker")` в сессии преподавателя. Для испытаний в кабинете снимите его до нагрузки, во время неё и после завершения. `running` означает занятых исполнителей, `waiting` — текущую очередь, `peakWaiting` — пик за время жизни сервера. `admitted` и `rejected` — накопительные счётчики допусков и отказов по вместимости. `waitSamples`, `waitP95Milliseconds` и `waitMaxMilliseconds` описывают до 256 последних допусков, включая нулевое ожидание при свободном исполнителе. Замер заканчивается, когда код сервера продолжает работу с полученным разрешением. Отменённые до допуска запросы не попадают в выборку ожидания. Пик включает всю работу процесса с момента запуска. Для отдельного приёмочного замера используйте новый изолированный процесс.

На оборудовании кабинета остаются установка и масштаб интерфейса Windows 10 LTSC 1809, связь по физической LAN, длительная нагрузка с реалистичными историями и измерение серверной очереди. Проверки аварийного выключения и восстановления из резервной копии выполняются отдельными сценариями.

## Повторный запуск

После основных замеров команда тестирования также прошла с тремя переменными окружения ниже и уже собранными Release-бинарниками.

Из корня репозитория в PowerShell с .NET 10 SDK:

```powershell
$loadBuild = Join-Path (Get-Location).Path '.codex/classroom-load-build'
dotnet build avalonia/Classroom.sln -c Release --artifacts-path $loadBuild -p:RestoreLockedMode=true
if ($LASTEXITCODE -ne 0) { throw 'Release build failed' }
$env:CLASSROOM_TEST_ROOT = (Resolve-Path 'avalonia').Path
$env:CLASSROOM_TEST_SERVER = Join-Path $loadBuild 'bin/Classroom.Server/release/Classroom.Server.dll'
$env:CLASSROOM_TEST_WORKER = Join-Path $loadBuild 'bin/Classroom.Worker/release/Classroom.Worker.dll'
dotnet test avalonia/tests/Classroom.UiTests/Classroom.UiTests.csproj -c Release --artifacts-path $loadBuild --no-build --filter 'FullyQualifiedName~ClassroomLoadTests' --logger trx --results-directory '.codex/classroom-load-results'
```
