# DS18B20 / 1-Wire · 16 ноября 2026

Часть E11 после `836184e`, не завершение полной компонентной/MCU-матрицы. Отдельный исполняемый `Ds18b20` / `ds18b20-to92`; исторические Visual-детали и их JSON не преобразуются.

## Профиль и источники

[Datasheet Analog Devices](https://www.analog.com/media/en/technical-documentation/data-sheets/ds18b20.pdf): TO-92 с контактами GND / DQ / VDD, питание 3–5,5 В, −55…125 °C, 9–12 бит, максимальное преобразование 93,75 / 187,5 / 375 / 750 мс. Начальное показание 85 °C. ROM состоит из family 28h, серийного номера и CRC8; scratchpad также имеет CRC. Поддерживается питание через DQ, которому нужна сильная подтяжка на протяжении преобразования/копирования EEPROM. Reset принимается от 480 мкс; presence выбран от 30 до 150 мкс после release, внутри диапазона datasheet.

[Публичный пример Cirkit](https://docs.cirkitdesigner.com/component-simulation-code/27f57294-af31-4f8d-a6bf-e53141e6547b), componentId 38566 / version 10, simulation flags true: три вывода, температура среды 25 °C, начальное показание 85 °C, ROM/разрешение/busy. Сопоставление примера не является аудитом всей библиотеки. Материалы исследования лежат в игнорируемой `.codex/cirkit-component-audit/ds18b20-*`. Код/изображение Cirkit в приложение не копировались; права прямого использования ещё не установлены. Native/SVG используют собственный вектор корпуса.

## Исполнение и сохранение

- Собственные `ds18b20.cjs` и GPIO-адаптер: реальные стандартные временные слоты, LSB-first, Read/Match/Skip/Search ROM и Alarm Search, scratchpad/CRC, Read Power Supply, Convert T, Write/Copy/Recall Scratchpad. Температура захватывается при начале преобразования, signed raw quantized по разрешению. Это идеальный цифровой профиль без шума и аналоговой погрешности.
- AVR и Pico исполняют скомпилированный код OneWire/DallasTemperature. Готовые адреса, результаты Arduino-вызовов или строки serial не подставляются. Pico использует SIO GPIO; PIO/overdrive и все pad/IRQ-режимы отдельно не приняты. До восьми устройств, в том числе на общей шине; ROM устойчиво выводится из ID детали с CRC. Новая деталь получает новый адрес, сохранённая копия сохраняет прежний.
- Native связывает DQ с одним GPIO через wire/breadboard nets, проверяет общую GND, питание и внешнюю резистивную подтяжку 1–100 кОм. Для Pico остаётся проверка опасных 5 В. Питание через DQ выбирается соединением VDD с GND; OneWire удерживает GPIO HIGH. Слабой подтяжки для busy-операции недостаточно. Модель не является расчётом тока/фронтов/ёмкости длинного кабеля; отдельный управляемый внешний MOSFET/источник сильной подтяжки в native ещё не подключён.
- TH/TL/config после завершённого Copy Scratchpad передаются как записи памяти. Worker останавливает CPU при накоплении восьми; одновременное завершение ещё до восьми jobs может дать внутренний остаток, выдаваемый последующими ответами не более чем по восемь. Порядок/остаток сохраняются при тёплой замене MCU. UI сохраняет каждую полученную запись в `DeviceMemory` и `device-memory-write`; состояние среды — в `control-change`. Копирование настроек обратно во входной descriptor не отменяет ещё не сохранённые scratchpad-изменения текущего физического датчика.
- Optional `deviceMemory` — три байта TH/TL/config с проверкой диапазона и зарезервированных битов; при null поле отсутствует. Новая модель добавлена в конец PartKind, версия JSON 1 и SQLite не меняются. Contract inspector и обе роли обновлять совместно. Старые схемы сохраняют точный JSON. История, immutable сдачи, проверочная копия, оценка и backup используют общий существующий механизм.
- Во время работы свойства показывают ROM/показание/разрешение; ползунок меняет температуру среды, код не переписывается. Шаблон проверяет занятость GPIO и использует настоящие библиотеки. Полного raw 1-Wire bit trace в серверном журнале пока нет. Последний ещё не возвращённый RPC при Stop, как и другие peripheral summaries, не объявляется гарантированно сохранённым; финальная остановка/долговечность всех таких событий остаётся отдельной приёмкой.

## Автономные библиотеки и коррекция reset

Закреплены [OneWire 2.3.8](https://github.com/PaulStoffregen/OneWire/tree/v2.3.8) и [DallasTemperature 4.0.5](https://github.com/milesburton/Arduino-Temperature-Control-Library/tree/v4.0.5). У обеих MIT; у OneWire notice в исходниках, у Dallas сохранён LICENSE. Полные папки, включая notices, входят в оба подготовленных runtime и будущую упаковку. На занятии загрузок не требуется; первоначальная подготовка SDK требует сеть.

AVR GCC 16.1 с закреплённым core измеренно исполнил библиотечный `delayMicroseconds(480)` как LOW 479,25 мкс. Строгая модель отклонила этот reset: реальные AVR-тесты получили −127/неверный поиск, Pico прошёл. Вместо ослабления 480-мкс границы единственный upstream reset изменён на номинальные 500 мкс; это допустимая длительность стандартного режима. Последующие реальные библиотеки Uno/Mega/Pico прошли, а reset 479,25 мкс по-прежнему не получает presence.

`prepare-onewire-libraries.ps1` устанавливает обе закреплённые зависимости без зависимостей других версий; `patch-onewire-timing.ps1` сначала проверяет наличие/версии обеих библиотек, затем точный SHA256 OneWire.cpp. Чужая или неполная папка отвергается с сохранением файлов. Коррекция идемпотентна, marker `offline-onewire-libraries-v2.json` явно фиксирует изменённый источник и происхождение:

- исходный SHA256: `A252B02F7F7E8A49F8C96C81ADD003175CE72E7B9C927D9D98514937D2656013`;
- изменённый SHA256: `282FF26244D8E6518C5474E9E7326DFA326DBCE4FE54116A281D7EC72107C942`;
- patch: `reset-500us-v1`. Это OneWire 2.3.8 с документированной коррекцией, не неизменённый upstream.

Base `prepare-electronics.ps1` и отдельный `prepare-pico.ps1` готовят этот профиль; `copy-electronics-runtime.ps1` требует библиотеки и v2 marker. CompilerRuntime fingerprint отделяет их от прежнего SDK-кэша. Готовый старый SDK дополняется при подготовке; неизвестный исходник автоматически не перезаписывается.

## Доказательства и открытая приёмка

Фактические прогоны и исправленные начальные отказы — в [едином baseline](next-version-baseline-2026-11-04.md). Подтверждены реальные библиотеки Uno/Mega/Pico, external/parasite, отрицательная температура, многоточечный поиск восьми датчиков, EEPROM, native-сохранение/повторное открытие, запущенная сданная копия/история/оценка/backup. Отдельно прошла общая Pico-схема DS18B20 + DHT11 + HC-SR04 + OLED. Визуально просмотрены Uno 900, Pico 1320 и преподавательская копия; оба редактора показывают live 31,5 °C / 9 бит. Это не закрывает общий E13-аудит интерфейса и точную графическую совместимость Cirkit.

Открыты полная аппаратная/компонентная матрица, прочие электрические топологии и strong-pullup устройства, PIO/расширенные временные режимы, полный периферийный журнал, свежее опубликованное приложение и физические Win10/offline LAN/35 клиентов. Старые установщики среза `6406e6d` этих последующих датчиков не содержат. GitHub не обновлялся по просьбе владельца; импорт и учебная редактура отложены, ИИ исключён. Личные приложения/данные/Windows policies не менялись; защиты содержимого файлов пока нет.
