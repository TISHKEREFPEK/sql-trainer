# Цифровые выводы ESP32-S3 · 19 ноября 2026

## Плата в редакторе

Включите отдельно подготовленный комплект GPIO через `CLASSROOM_ESP32S3_GPIO_RUNTIME` и Arduino SDK через `CLASSROOM_ESP32S3_RUNTIME`. В каталоге нативного редактора появится **ESP32-S3-DevKitC-1 · GPIO**. Проект использует распиновку J1/J3 модели v1.1 и отдельный ID `esp32s3-devkitc-1-gpio`. Выводы на новой иллюстрации совмещены с контактами. [Распиновка производителя](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1.html#header-block)

В коде указываются номера GPIO. Для проверки подключите кнопку между GPIO12 и землёй и светодиод через резистор к GPIO39. Компиляция использует прежний автономный Arduino-профиль. В запущенной схеме состояния меняются через изолированный обмен, при остановке выходы освобождаются. Плавающие входы сохраняют высокое сопротивление, а уровни вне диапазона цифровых выводов вызывают сообщение. В этом профиле закреплено питание от виртуального USB. Периферийные схемы, последовательный монитор, программное управление сбросом и классная поставка остаются в работе.

Новый проект хранится как JSON v1 с отдельным типом `Esp32S3`. Сдачи требуют актуальных Server, Teacher и Student. Старые проекты с Visual-компонентами ESP32 открываются со своими исходными ID и выводами.

В расширенном прогоне `esp32s3-scheme-acceptance` прошли 19 проверок, включая загрузку прошивки в редакторе, щелчки мышью, реакцию светодиода и остановку с освобождением выхода. Тест каталога в этом прогоне ожидал только две прежние платы. Повтор с обновлённым ожиданием прошёл в двух режимах, с подключённым комплектом и без него. Схема и расположение выводов проверены на снимке окна 1320 × 940.

## Модель эмулятора

Работа относится к E11. Патч добавляет цифровой тракт ESP32-S3 поверх проверенной загрузки Arduino из флеш-памяти. В QEMU подключены регистры GPIO и IO MUX по штатным адресам, входные уровни обеих банков и прерывание GPIO через матрицу прерываний. [Техническое руководство ESP32-S3, глава 6](https://documentation.espressif.com/esp32-s3_technical_reference_manual_en.pdf) · [Исходный ESP32-S3 QEMU](https://github.com/espressif/qemu/tree/40edccac415693c5130f91c01d84176ae6008566)

QEMU принимает для каждой линии `pad-in` низкий или высокий уровень либо плавающий ввод. `pad-level` сообщает уровень, `pad-driven` — активно ли плата его выставляет. Модель учитывает направление, два банка защёлки, подтяжки, открытый сток, инверсию цифрового выхода, маски и прерывания по фронту и уровню. Регистры маршрутизации других сигналов хранят настройки. Подключение ADC, PWM, SPI/I2C, UART к выводам, RTC IO MUX, фильтры, сон и сеть требуют отдельной модели и проверки. [Матрица исходного QEMU](https://github.com/espressif/esp-toolchain-docs/blob/main/qemu/README.md)

Из открытого выпуска PICSimLab 0.9.3 проверен состав Windows-архива. В нём поставляются ROM для ESP32 и C3. В исходной ветке `picsimlab-esp32` на проверенном `885a6e7` S3 использует отдельное устройство GPIO и штатную машину. Дополнительную S3-машину с обратными вызовами описывает Velxio, соответствующая сборка требует своего архива исходников. Для этого шага базой выбран уже проверенный Espressif QEMU 9.2.2. [PICSimLab 0.9.3](https://github.com/lcgamboa/picsimlab/releases/tag/v0.9.3) · [Документация сборки Velxio](https://github.com/davidmonterocrespo24/velxio/blob/master/docs/BUILD-QEMU.md)

## Повторение проверки

Патч применяется к чистому QEMU `40edccac415693c5130f91c01d84176ae6008566` командой `git apply --unidiff-zero`. Исходники и сборку Windows расположить в каталоге с коротким ASCII-путём. У MinGW и Meson в этом прогоне путь OneDrive с кириллицей ломал временные файлы и поиск ROM. Инструменты MSYS2 нужны только сборочному компьютеру. [Патч](../electronics/esp32s3-qemu/esp32s3-gpio.patch) · [Подготовка MSYS2 из архива](https://www.msys2.org/docs/installer/)

В MSYS2 UCRT64 нужны GCC, Python, ninja, meson, pkgconf, glib2, pixman, libgcrypt, make и diffutils. Из отдельного каталога сборки:

```bash
../qemu/configure --target-list=xtensa-softmmu --without-default-features --enable-gcrypt --disable-docs --disable-werror
ninja -j 8 qemu-system-xtensa.exe
```

Проверка использует штатный QTest на стандартном вводе и выводе в локальном процессе. Аргумент `--bios` указывает на папку со штатным `esp32s3_rev0_rom.bin` из подготовленного SDK. Аргумент `--flash` принимает флеш-образ 4 МиБ, собранный из приложенного Arduino-скетча через `Esp32S3Compiler.CompileArduino`. Для запуска разработческих проверок с DLL MinGW требуется `ucrt64/bin` в PATH запускающего сеанса. [Проверка регистров и выполнения](../electronics/esp32s3-qemu/check-gpio.py) · [Проверочный скетч](../electronics/esp32s3-qemu/gpio-probe.ino)

На Windows 11 x64 QEMU собран в MSYS2 UCRT64 с GCC 16.2.0, Meson 1.12.1 и Ninja 1.13.2. Проверки обеих банков GPIO, подтяжек, открытого стока, маски отсутствующего GPIO22, вывода и сброса прерываний прошли. Проверочный Arduino-скетч с `INPUT_PULLUP`, `attachInterrupt(CHANGE)` и `digitalWrite` загрузился. Изменение GPIO12 вызвало два прерывания и переключило выход GPIO39. Штатный QEMU с тем же ROM останавливает проверку на отсутствии выходов `pad-level`.

Патч относится к реализации QEMU и сохраняет её лицензию. Поставка для кабинета требует проверки соответствующих исходников, ROM, библиотек и запуска на Windows 10 LTSC.

## Изолированный сеанс GPIO

`Esp32S3GpioRunner` запускает прошивку в AppContainer с теми же ограничениями памяти и дочерних процессов, что и проверочный запуск Arduino. QTest использует унаследованные каналы stdin/stdout. Адреса регистров и команды формирует код сеанса. Гостевой Serial, сеть и monitor отключены в этом профиле. Ошибка протокола или остановка завершают процесс, после чего временная папка удаляется.

`ExchangePads` принимает уровни внешних соединений и возвращает считанный уровень, активное направление, значение выхода и настройки подтяжек. Удаление входа из набора освобождает ранее выставленный уровень. GPIO22–25 отвергаются до передачи команды. Опрос принимает несколько состояний регистров за один вызов. Контур для высокочастотных сигналов и соединение с виртуальной схемой остаются частью E11.

Для теста `CLASSROOM_ESP32S3_RUNTIME` указывает на подготовленный Arduino SDK. В `CLASSROOM_ESP32S3_GPIO_RUNTIME` задаётся отдельный каталог с `arduino-cli.exe`, папкой `data/packages`, собранным `sandbox-xtensa/qemu/bin/qemu-system-xtensa.exe` и его DLL, а также ROM в `sandbox-xtensa/qemu/share/qemu`. Обычный комплект остаётся пригодным для базовых тестов. Новый тест использует опциональную сборку и сообщает о пропуске при её отсутствии.

```powershell
dotnet test ./avalonia/tests/Classroom.UiTests -c Release --filter 'FullyQualifiedName~Esp32S3GpioRunnerTests'
```

В прогоне `esp32s3-gpio-proof` прошли 14 проверок GPIO, Arduino, bare-metal и изоляции. В AppContainer GPIO12 принимал внешний сигнал, действующая программа меняла GPIO39, удаление входа возвращало подтяжку. Проверены повторный запуск и отмена работающего гостя. Отдельный сборочный комплект и тесты Windows 10 LTSC ещё требуются.
