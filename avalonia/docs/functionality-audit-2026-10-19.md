# Проверка функционала · 19 октября 2026

Проверены текущая Avalonia и исходники последней сборки Electron из `codex/desktop`. Исправлены обход clipboard-команд, обновление списка групп и сохранение ограничений из редактора альтернативного варианта. После исправлений проходят **27 тестовых случаев: 10 логики/API и 17 UI**, без ошибок и пропусков. Это не завершённая приёмка кабинета.

## Дефекты и изменения

### P1 · Команды SQL-редактора обходили проверку клавиш — исправлено

До исправления `ApplicationCommands.Cut.Execute` удаляла выделенный SQL в задании с `Restricted=true`. Событие KeyDown при этом не требуется, поэтому обработчик окна не защищал командный путь.

Перед стандартными binding редактора установлены обработчики Copy/Cut/Paste. Они блокируют действие и отправляют событие нарушения. Для обычных TextBox добавлены обработчики clipboard-событий, включая путь контекстного меню. Неотмеченные задания сохраняют обычное поведение.

Доказательство: регрессионный тест до изменения получил пустой SQL вместо исходного. После изменения проходят запрет команды, разрешение той же команды без ограничения, шесть сочетаний клавиш и три clipboard-события TextBox.

### P2 · Новые группы не доходили до открытого списка при опросе — исправлено

Полный Refresh обновлял группы, но регулярный Refresh(false) обновлял только отчёты и учеников. Группа, появившаяся после первоначальной загрузки вне этого полного обновления, отсутствовала в выпадающем списке. Обычное создание группы в одном исходном окне при этом воспроизводилось успешно — исходное утверждение «группы вообще не выбираются» не подтверждено для всех сценариев.

Список теперь обновляется и при опросе, сохраняет выбранную группу и не пересоздаётся без изменения состава. Созданная через форму группа сразу выбирается для нового ученика; ComboBox растянут по ширине формы.

Доказательство: тест опроса до исправления видел 2 пункта вместо 3. После исправления проходит. В нативном исправленном Teacher создана группа «Аудит UI — новая группа», затем ученик; API подтвердил GroupId именно этой группы.

### P1 · Ограничение терялось при сохранении альтернативного варианта — исправлено

Основная версия отправляла Restricted, альтернативная — только TaskJson. Общий флажок выглядел редактируемым, но его значение для альтернативы не сохранялось.

SaveVariantRequest получил необязательное поле Restricted. Сервер сохраняет вариант и ограничение одним SaveChanges. Старый клиент без поля не меняет прежнее ограничение. Назначенные условия не переписываются.

Доказательство: API-тест включает/выключает ограничение через сохранение варианта, проверяет неизменность выданного условия, отказ ученику (403) и совместимость запроса без нового поля.

### P2 · Ошибка Windows-защиты снимков была невидима — исправлено

Результат SetWindowDisplayAffinity раньше игнорировался. Теперь приложение проверяет вызов и читает установленное значение обратно через GetWindowDisplayAffinity. Если Windows не применяет защиту, ученик получает сообщение об ошибке; запрет копирования продолжает действовать. Подпись преподавательского флажка явно упоминает захват окна.

На исходном тестовом Student с включённым ограничением Windows вернула affinity **17 (0x11)**; при захвате было видно окно позади, а не ученический экран. В неотмеченном личном Student affinity была **0**, что соответствует выбранным требованиям. При первоначальном осмотре в личной базе ни одно задание не было отмечено как Restricted.

Это проверка API и доступного Windows-захвата на одном ПК. Win+Shift+S/PrintScreen вручную не нажимались в этом проходе; Windows 10 и внешний захват требуют отдельной приёмки. [Microsoft описывает область действия и ограничения этого API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity).

### P3 · После запуска оставалась надпись «Запускается сервер…» — исправлено

После успешного открытия формы входа преподавателя стартовый статус очищается. Проверено в новом нативном Teacher: строка статуса пустая до входа.

## Что ещё не закрыто

1. **Полное логирование.** В журнале есть проверки, ошибки, clipboard и подсказки; в статистике — активность и завершения. Нет единого журнала всех входов, каждого редактирования, назначения групп, административных изменений и действий в настройках. Overview показывает последние 1000 попыток. Требование «логировать всё» выполнено частично.
2. **Работа после выключения ПК/закрытия окна без сети.** Несохранённый черновик и незавершённая клиентская операция находятся в памяти открытого Student. Для гарантии при внезапном выключении нужна отдельная постоянная локальная очередь/копия. Перезапуск серверного теста не доказывает сохранение последних несинхронизированных символов на отключённом ПК.
3. **Полный перенос сайта.** Нет web-гостя, импорта сайта D1 и браузерного группового входа; нет очереди повторения сложных заданий. Эти сценарии не следует обозначать перенесёнными только по совпадению каталога.
4. **Редактор и навигация.** Нет UI редактирования общего словаря и явного переназначения начатых работ. Смена категории/темы обновляет список, но сама не открывает первое задание — отличие от desktop. Длинные формы, DPI и клавиатуру нужно проверить с преподавателем.
5. **Поставка и сеть.** В этом проходе не устанавливались новые установщики, не проверялись Windows 10, обновление поверх старой версии, tray, лимит памяти worker под нагрузкой реального кабинета и LAN между физическими ПК. Не менялись firewall и настройки сети колледжа.
