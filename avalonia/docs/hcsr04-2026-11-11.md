# HC-SR04 · 11 ноября 2026

Часть E11, не завершение компонентной/MCU-матрицы. Отдельная исполняемая модель `Hcsr04` / `hcsr04-5v`; старые Visual-модели/идентификаторы не преобразуются.

## Профиль и первичные источники

[Пример Cirkit](https://docs.cirkitdesigner.com/component-simulation-code/f7a95729-a811-496b-83f5-7789de376adf), componentId 38567, version 6, simulation flags true: VCC / TRIG / ECHO / GND; начальное расстояние 100 см, цель присутствует. Это пример компонента, не вся библиотека. Полученные материалы лежат только в игнорируемой `.codex/cirkit-component-audit/hcsr04-*`. Сторонние исходники/иллюстрации в приложение не переносились; право прямого использования ресурсов Cirkit не установлено.

[Руководство ElecFreaks на сервере SparkFun](https://cdn.sparkfun.com/datasheets/Sensors/Proximity/HCSR04.pdf): модуль 5 В, четыре контакта, Trig не короче 10 мкс, восемь циклов 40 кГц, диапазон 2–400 см, расчёт по длительности Echo, период измерений более 60 мс. Использован указанный там приближённый пересчёт `см = мкс / 58`. Это идеальная цифровая модель; акустические отражения/угол/площадь цели, шум, температура воздуха и погрешность реального датчика не моделируются.

Профиль принимает питание 4,5–5,5 В как выбранный рабочий допуск вокруг номинальных 5 В. Не объявляет поддержку отдельной версии HC-SR04 3,3 В. Начало Echo — через 200 мкс после завершения корректного Trig; расстояние и наличие цели фиксируются в этот момент, последующая правка не меняет текущий импульс. Выбран режим отсутствия цели без импульса Echo; пользовательский код получает тайм-аут. Клоны с длинным HIGH при отсутствии отражения этим режимом не описываются. Повторные Trig внутри 60 мс игнорируются.

## Реализация

- Собственные `hcsr04.cjs` / `hcsr04-gpio.cjs`: реальный GPIO Trig и запланированные изменения input level Echo через AVR clock events / Pico SimulationClock. pulseIn/digitalRead и машинный код не перехватываются. Учитываются снятие питания, захват параметров и продолжение внешнего импульса при замене MCU. HIGH, уже существовавший при включении питания, не считается новым Trig. До четырёх датчиков; приём Echo на несколько GPIO допускается, конфликт выходов/ролей отклоняется.
- CircuitHcsr04 определяет Trig по физическим nets; Echo связывается с GPIO через два решения существующей схемы для LOW/HIGH. Поэтому работают резистивные цепи/делители и breadboard, а не только прямой провод. Источник Echo использует выбранную модель выходного сопротивления 25 Ом; HIGH вычисляется от фактического питания. Это квазистатическое сопоставление логических уровней, не аналоговая симуляция фронтов/кабеля/RC и не полная модель всех согласующих полупроводников.
- Для Pico проверяется возможный HIGH, даже если сейчас цели нет. Прямые 5 В отклоняются до запуска; делитель 1 кОм / 2,2 кОм при номинальном питании даёт около 3,41 В в выбранной модели и проходит установленный предел 3,45 В. При ином питании/номиналах проверка выполняется заново. Недостаточный HIGH не превращается в вымышленный импульс: автоматически готовый шаблон для такой схемы не выдаётся. Во время работы MCU не может одновременно управлять GPIO Echo как выходом.
- `signals` — optional внутренний параметр CircuitSolver для расчёта состояний периферийного выхода. Без него HC-SR04 показан в DC idle LOW. Обычная схема/снимок не содержит исполняемых сигналов, версия JSON/SQLite не меняются. Модель добавлена в конец PartKind, серверный inspector и роли следует обновлять совместно.
- Native-каталог, оригинальный вектор корпуса/выводов, SVG, изменение расстояния и кнопка наличия цели. Control-change и serial output используют прежнюю пошаговую историю, назначения, immutable сдачи и преподавательскую копию. Старый код не меняется без команды. Шаблон использует встроенный pulseIn с тайм-аутом и интервалом; новых SDK-библиотек/скачиваний не требуется.

## Доказательства и открытая приёмка

Результаты фактических прогонов находятся в [едином baseline](next-version-baseline-2026-11-04.md). Прошли 22 выбранных regression-сценария; дополнительная проверка настоящего attachInterrupt обнаружила и помогла исправить повторные IRQ от неизменного Pico raw input. После исправления обработчики Uno/Pico получили ровно два фронта Echo. Тот же дефект найден в общем host-input пути: неизменный LOW вызывал повторные handlers. Общий собственный pico-gpio-input.cjs сохраняет edge latches, поддерживает LOW/HIGH level status и не создаёт фронт из повторного sample; используется worker и HC/DHT bridge. Подтверждены ноль IRQ на стабильном входе и один на реальном переключении. Итоговый набор из 25 HC/DHT/watchdog/input сценариев прошёл; LOW/HIGH level flags подтверждены чтением MMIO. Полный аппаратный IRQ-охват этим не заявляется. Первый реальный pulseIn на AVR при включённых прерываниях вернул 5771/5772 мкс для идеального импульса 5800 мкс. Закреплённый Arduino AVR core 1.8.6, `cores/arduino/wiring_pulse.c` прямо отмечает преимущество noInterrupts для этой функции; её ASM считает циклы polling loop, а не время обслуживания ISR. [Первичный Arduino core](https://github.com/arduino/ArduinoCore-avr/blob/1.8.6/cores/arduino/wiring_pulse.c). Проверка физической длительности выполняется в noInterrupts-контексте, а UI-проверки используют обычный сгенерированный код с допустимой погрешностью измеряющей функции. Точность модели не подгонялась к первому числу.

Открыты полная аппаратная приёмка IRQ/PIO/capture и библиотек с собственными timer modes, акустика/взаимные помехи нескольких датчиков, аналоговые фронты/нагрузка/все преобразователи уровней, точная графика Cirkit и свежая поставка/физические Win10/offline LAN/нагрузка класса. Это не доказательство завершения E11/E14. Импорт/учебная редактура/GitHub по-прежнему отложены; рабочие установки/базы/Windows policies не менялись.
