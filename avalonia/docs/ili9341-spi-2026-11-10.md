# ILI9341: аппаратный SPI и native-редактор · 10 ноября 2026

Продолжение E01/E11 после `531dbc6`: отдельный **TftSpi / tft-ili9341-spi** с девятью контактами, физической проводкой, цветным изображением, шаблоном Uno/Mega/Pico SPI0/SPI1 и общим сохранением/сдачей/проверочной копией. Старый Visual ILI9341 и его hash-ID сохранены; никакие прежние схемы автоматически не преобразуются. Это не вся SPI/Cirkit-приёмка: обязательный остаток указан ниже. Импорт отложен владельцем.

## Проверенная граница сравнения

[Официальные примеры компонентов Cirkit](https://www.cirkitdesigner.com/docs/custom-simulation-parts/component-examples) включают ILI9341 с просмотром исходника. На 10 ноября публичная карточка `b6ad130a-8862-41a2-bf57-05cc26b0312a`, componentId 38568 / version 6, возвращает hasSimulationLogic=true / isSimulationCodeRunnable=true. Источник: [страница просмотра компонента](https://docs.cirkitdesigner.com/component-simulation-code/b6ad130a-8862-41a2-bf57-05cc26b0312a). Это точная проверенная карточка, не предположение по названию похожей платы.

Проверены 9 контактов в порядке **VCC, GND, CS, RST, D/C, MOSI, SCK, LED, MISO**, framebuffer 240×320, four-wire SPI, readback, ориентация/цвет/прокрутка. В этом интерфейсе нет выводов touch/SD: дополнительные библиотеки touchscreen/SD не требуются для переноса именно этой модели дисплея. Проверяемый Cirkit-модуль принимает питание 3–5,5 В; это не разрешение подавать 5 В непосредственно на bare ILI9341 silicon. При native-интеграции нужно явно определить модуль с согласованием уровней и сохранить проверку Pico GPIO.

Метаданные геометрии: numDisplayCols=18.30709 / numDisplayRows=30.55118; header pins x=502.90315+100*i mil, y=63.46929 mil, i=0..8. Эти факты задают расположение новых логических выводов; существующие проекты/ID/выводы старой иллюстрации не менять. Оригинальная native-геометрия 240×400,5 использует эти пропорции; RGB-поверхность 210×280 сохраняет 3:4, выводы, подписи и вся деталь трансформируются вместе. Это собственный вектор, не перенесённый SVG Cirkit и не заявление о точном внешнем виде всех carrier boards.

Публичные материалы сравнения сохранены только в игнорируемой `.codex/cirkit-component-audit/`, не в Git. ## Реализованное основание

- `ili9341.cjs`: фиксированная GRAM, RGB565/RGB666, окна/продолжение записи/чтение, 4 ориентации MADCTL с BGR-панелью, display/sleep/backlight/inversion, vertical scroll, partial/idle режимы и нужные init/read registers. Sleep-out имеет функциональную задержку 120 ms. Power loss сбрасывает GRAM, software/hardware reset очищает настройки, не изображает выключение питания. Это цифровая функциональная модель; analog gamma/power ramps/полный набор режимов контроллера ещё не приняты.
- `spi-displays.cjs`: до двух панелей на worker, типизированные GPIO/constant CS/DC/RST/LED, проверка bindings до обновления, завершение байта после времени передачи, отмена при изменении критических линий (включая краткий CS pulse), продолжение через границу frame при прежней конфигурации. Неверный/отсутствующий MISO не выдаёт ID контроллера; конфликт нескольких ответов отклоняется. RGB888/base64 кадры укладываются в прежний предел ответа.
- `avr-spi.cjs` / `pico-spi.cjs`: настоящие hardware SPI peripheral callbacks, собственное вычисление mode по регистрам (вендорские getters имеют другое кодирование). Выбор Uno/Mega pin roles и Pico controller/mux, частота/битовый порядок/время передачи. Оригинальные AVR8js/RP2040js не менялись; Arduino-функции не перехватываются. На этом шаге поддержаны **8/16-bit words и mode 0/3 для TFT**, не полный physical SPI waveform/debugger.
- Worker API получил optional spiDevices / tftDisplays; C# DTO и Step-параметры необязательные. Старые Step-вызовы совместимы. Новый TftSpi допущен в server inspector, Version=1 и SQLite не меняются; Server и роли обновлять совместно. Pico warm reset сохраняет внешнюю Map TFT-панелей на физическом clock, новые controller bindings создаются отдельно. Полная TFT/reset-приёмка ещё нужна.

Реальные протокольные первоисточники: [Ilitek ILI9341 V1.11](https://cdn-shop.adafruit.com/datasheets/ILI9341.pdf), [официальная библиотека Adafruit 1.7.0](https://github.com/adafruit/Adafruit_ILI9341/tree/1.7.0). Схемы уровней отдельных carrier boards различаются: [пример производителя с level shifter](https://www.adafruit.com/product/1480). Последний пример не подменяет идентичность проверенной Cirkit-модели.

## SDK и повторение

`prepare-spi-libraries.ps1` устанавливает закреплённую Adafruit_ILI9341 1.7.0 через Arduino library index, `--no-deps`. Существующие GFX 1.13.0/BusIO 1.17.4 используются для SPI display; дополнительные touch-библиотеки из library.properties не включаются в этот блок. Runtime должен быть подготовлен базовым скриптом. Отличающаяся/неполная существующая папка не перезаписывается. Временные ARDUINO_DIRECTORIES_* восстанавливаются после вызова.

Обычный `prepare-electronics.ps1` вызывает supplement и на fast path; `prepare-pico.ps1` копирует полную библиотеку с лицензией из base SDK, а готовый Pico повторно проверяется без наличия base. Новое `offline-spi-libraries-v1.json` дополняет прежние core markers; `copy-electronics-runtime.ps1` включает библиотеку и marker в обе роли. Никаких сетевых загрузок при запуске ученика не добавлено. Старые установщики `6406e6d` этой библиотеки/RTC/watchdog/TFT не содержат; новые установщики не собирались.

```powershell
./avalonia/scripts/prepare-electronics.ps1
./avalonia/scripts/prepare-pico.ps1
# Pure controller / bus:
./avalonia/artifacts/electronics-runtime/node.exe ./avalonia/tests/check-ili9341.cjs
./avalonia/artifacts/electronics-runtime/node.exe ./avalonia/tests/check-spi-displays.cjs
```

Для .NET проверок задать CLASSROOM_ELECTRONICS_RUNTIME / CLASSROOM_PICO_RUNTIME и использовать Ili9341FoundationTests. Точные результаты и ограничения проверки — в [baseline](next-version-baseline-2026-11-04.md).

## Native-связка после 531dbc6

- CircuitSpi использует CircuitConnections: wire/breadboard strips, общую землю, power/LED, реальные GPIO и константы управления. Источники/замкнутые или неоднозначные data nets не становятся валидными SPI descriptors. Неправильные аппаратные роли не возвращают ID; CodeGuide объясняет соединения. MISO необязателен для рисования. GPIO Pico по-прежнему проверяются на 3,3 В.
- Режим модуля явно задан как регулируемое питание 3–5,5 В / level-tolerant inputs / MISO 3,3 В. Это цифровой carrier profile; не разрешение 5 В на bare ILI9341 или GPIO Pico.
- Оригинальный TftDisplayFace, catalog preview, RGB bitmap с освобождением при detach, PartArtwork header/transform/экспорт схемы. Локальный renderer не пишет framebuffer в историю.
- Общий TftCodeGuide по фактической проводке: Uno/Mega SPI, Pico SPI/SPI1, 4 MHz, pin conflicts с прочими устройствами, управление подсветкой GPIO. Неопределённая проводка блокирует генерацию, исходный код сам не заменяется.
- ElectronicsScreen передаёт bindings/принимает кадры одинаково у ученика и в изолированной teacher-copy, очищает кадры на остановке. Server inspector принимает TftSpi без новой SQLite-миграции. Обычные save/journal/submission/review/backup сохраняют проект, код, действия и оценку; raw SPI transaction journal ещё открыт.
- Потеря signal connectivity теперь отменяет передачу, сохраняя питание/GRAM. Только power loss очищает память; transient CS продолжает отменять незавершённое слово.

## Обязательный остаток до полной приёмки

1. Bounded SPI diagnostics/history: полезные команды/ошибки/счётчики без неограниченного хранения каждого pixel byte. Прежние code/run/input/user/teacher действия уже сохраняются; не объявлять их полным протокольным SPI журналом.
2. Software GPIO SPI по реальным edges и произвольным допустимым GPIO; остальные word sizes/advanced controller modes. Hardware 8/16-bit mode0/3 не заменяет всю SPI-периферию.
3. Две панели, дополнительные constant control/MISO/CS/GPIO-LED конфигурации, TFT при watchdog reset/разрыве проводки, совместная I2C/SPI нагрузка и длительная ресурсная проверка. Цифровая модель не заявляет analog gamma/power transient fidelity.
4. Подробная графическая приёмка вращения/растяжения/DPI/экспорта/больших схем. Прямые source/SVG Cirkit не включены: условия на ресурсы по-прежнему требуют отдельного подтверждения, собственный вектор не закрывает требование точного переноса.
5. Новый TFT verifier из опубликованных Teacher/Student EXE, оба SDK payload/установщики и физический Win10/offline/LAN. Установщики 6406e6d не содержат последующих RTC/watchdog/TFT; рабочие приложения/личные данные/GitHub не обновлялись.
6. Остальная MCU/компонентная матрица, ESP32 и остальные E00–E14 остаются в полном объёме; импорт отложен, не выполнен.
