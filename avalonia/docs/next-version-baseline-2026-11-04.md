## Основание ESP32-S3 · 16 ноября 2026

После `b43c4ef` добавлено отдельное bare-metal основание CPU/RAM/UART, не новая исполняемая плата редактора и не Arduino. [Канонический профиль/первичные источники/следующие шаги](esp32s3-foundation-2026-11-16.md). Новые SDK/кэши/прошивки исследований лежат только в игнорируемой `.codex/esp32-probe`; личных учебных данных нет. QEMU GPIO/IOMUX — upstream stub, SPI/I2C/LEDC/Wi-Fi/RMT/native/поставка и вся остальная матрица остаются открытыми.

- Первичная неизолированная проба **только собственного фиксированного исследовательского исходника**, без ученических программ: официальный GCC скомпилировал настоящий Xtensa ELF, QEMU записал `real-xtensa: hello` в UART0 и отдельную строку в UART1. Это не было принято за достаточную безопасность/полноту. Исходник/ELF/команды сохранены в игнорируемом probe; такой fallback для пользовательской компиляции не добавлен.
- `esp32-first`: **0 passed / 5 failed**, 8 с. Официальный GCC x64 14.2.0_20260121 не запускается в AppContainer (Windows 623). PE показывает отсутствующую base relocation table. `esp32-relocations`: **0/5**, 7 с — исследовательское добавление неиспользуемой relocation не исправило готовый драйвер: 0xC0000005, в том числе вне sandbox. Patch отвергнут, файл удалён из product-исходников; изменённый SDK не используется. `esp32-x86`: **0/5**, 11 с — официальный x86 вариант получил тот же 623. Архивы проверены SHA256; изменения Windows policies/снятие изоляции не предпринимались.
- Выбран неизменённый Espressif Clang 19.1.2_20250312. `esp32-clang`: **0/5**, 12 с — driver восстанавливал физический путь с кириллицей и не мог запустить дочерний frontend. no-canonical-prefixes/integrated cc1/явный linker path сохраняют drive aliases. `esp32-clang-paths`: **1 passed / 4 failed**, 6 с — запрет include личного синтетического файла уже прошёл, но LLD аварийно завершился. Программа с RAM-переменными воспроизвела LLD failure **также вне AppContainer**; отказ не обошли простым hello world. Штатный native GNU ld 2.43.1 из того же Clang bundle с полноценными PE relocations собрал эту программу; LLVM assembler включён явно, GCC EXE/PE patch не требуются.
- `esp32-native-linker`: **2 passed / 3 failed**, 6 с. ELF/host include guard прошли, QEMU завершился до исполнения. `esp32-qemu-diagnostic`: **1 failed**, 2 с — сообщение allocate 1073741824 bytes for JIT buffer. QEMU default 1 GiB не помещался в прежний 768 MiB process job limit. Вместо повышения пределов или снятия AppContainer задан TCG cache 32 MiB / single host thread.
- `esp32-jit-bounded`: **5 passed / 0 skipped**, 14 с. Настоящие Clang/S3 инструкции вычисляют D9 из volatile initialized RAM/BSS, отдают отдельные UTF-8 UART0/1 с русским текстом/emoji; invalid ELF machine/bounds/entry/MMIO/writable code отвергаются. Шесть Esp32S3FoundationTests (добавлен реальный гостевой simcall open личного синтетического файла, ответ DENIED), прежние AVR compile/run/compiler-errors и Pico bare-metal GPIO/ADC/независимые UART. UART-строки/память — результат исполняемого кода, не подстановка API; данные преподавателя/ученика не менялись. Числа пересекающихся прогонов не суммировать как число уникальных проверок.
