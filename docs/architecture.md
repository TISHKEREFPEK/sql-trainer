# Архитектура

## Native LCD и шина I2C · 7 ноября 2026

`avr-devices.cjs` создаёт TWI/SPI с векторами выбранного MCU; `lcd-i2c.cjs` связывает TWI с PCF8574/HD44780. Native-проверка вычисляет питание и реальные сети SDA/SCL; команды Wire исполняются в AVR. Новый тип LcdI2c и необязательный `ElectronicsChange.I2cIo` расширяют JSON проектов/журналов, старые null-поля не записываются. `ElectronicsSync.Drain` ожидает параллельные снимки/историю и продолжает её пакеты, не объявляя отсутствие изменений черновика остановкой истории. SQLite/D1 не меняются, native-роли/Server обновлять совместно. Модель/границы/источники описаны в [native-архитектуре](../avalonia/docs/architecture.md); весь объём E11 ещё открыт.

## Профили AVR-исполнителя · 6 ноября 2026

Общий `avr-boards.json` задаёт FQBN/память/карту сигналов Uno и Mega. Отдельные конфигурации периферии и адаптация UART в `avr-devices.cjs`; vendor AVR8js не изменён. Компиляция остаётся в прежнем AppContainer; исполнение — отдельный ограниченный по памяти Node runner. Редактор/solver/кодогенератор и проверочная копия выбирают профиль по новому типу Mega или прежнему Uno; старые Visual/Mega не преобразуются. Кадры содержат независимые serialPorts и размер ожидающего ввода. Необязательное `ElectronicsChange.SerialIo` сохраняет порт/текст в прежнем ChangeJson; null не сериализуется, старые журналы читаются. SQLite/D1 не меняются, native-роли/Server обновлять совместно. Подробности — в native-архитектуре; E11 целиком не завершён.

## Общие native-результаты · 6 ноября 2026

`LessonSqlPractice` хранит наблюдение свободной работы курса в конкретном занятии, отдельно от исполненного Assignment и обязательной выдачи. Обновляется в тех же транзакциях/квитанциях; не является SQL-базой для запуска запросов. `LessonSessions.SqlPracticeTrackingAt` фиксируется только при первом старте новой пары: старые/восстановленные занятия без отметки не объявляются полностью записанными. Миграции `20261106154629_LessonSqlPractice`, `20261106155053_SqlPracticeCoverage` не заполняют пропуски догадками.

`ClassroomResults` формирует общий read-only вид SQL/назначенных схем, сводки, трудности и CSV с одними фильтрами. Персональный знаменатель SQL курса общий с `LearningAnalytics`; клиент только отображает расчёт. `LessonRoster` фиксирует ФИО/группу при старте и добавляет новых зарегистрированных/вошедших учеников. Исторический ID группы из одного сохранённого названия не выводится. Миграция `20261106151035_ResultsRoster` добавляет состав, отметку полноты и `Profiles.ResultsMode`; старые таблицы/колонки и пароли сохраняются. Подробности — в native-архитектуре. Учебный SQL по-прежнему исполняется только отдельным worker.

## Совместимость прежнего электронного outbox · 5 ноября 2026

ElectronicsBackgroundDelivery объединяет прямые штатные `.history` и `.json.sync.json` текущего профиля/сервера. Без индекса допускается только отсутствующая история либо папка с единственным `open.lock`; фрагменты страниц/backup/temp требуют восстановления. Legacy-передача берёт прежний outbox, удерживает ту же directory lease, не создаёт журнал и не угадывает LessonId. Прежние свободные отчёты сохраняют отсутствие занятия; назначение берётся из имени/проверенного содержимого очереди.

Обязательные поля outbox валидируются без генерации отсутствующего ClientId; формат корректных прежних файлов читается. Обычный редактор также работает без автосброса. ElectronicsOutboxRecovery проверяет backup/контекст/привязку и хеши файлов, показывает явный выбор через MainWindow.Safe; восстановление сохраняет оригинал и не меняет историю/UUID сдач. Отказ конструктора освобождает ресурсы, отказ Persist блокирует сеть до фиксации. Пауза разрешает локальное восстановление, сохраняя запрет редактирования/запуска. Подробности и границы — в native-архитектуре; доказательства — в baseline. Контракт сервера и модель SQLite/D1 не меняются.

## Фоновый обход электронной истории · 5 ноября 2026

MainWindow запускает отдельную от SQL фоновую очередь только после student-входа. ElectronicsBackgroundDelivery выбирает прямые штатные имена персональных файлов по SHA-256 отпечатка/ID профиля, сверяет метаданные индекса и имя назначения; каждый индекс полностью проверяется штатным HistoryStore под эксклюзивной блокировкой. ElectronicsSync в строгом режиме не восстанавливает повреждение случайной новой копией. Сначала прежний outbox передаёт снимок/отчёты, затем история передаётся с исходным занятием. Общий контракт/схема БД не меняются.

Один проход обрабатывает одну копию/контекст, сетевой этап ограничен 10 секундами, выбор круговой; проверенные неизменившиеся файлы повторно сверяются не чаще минуты. Перед открытием редактора, новым входом/выходом и завершением окна текущая передача отменяется с ожиданием освобождения файлов. На диске не сохраняются токены, фоновая очередь привязана к конкретному student-сеансу. Детали и открытые границы — в native-архитектуре.

## Серверная история электроники · 5 ноября 2026

Миграция `20261105183612_ElectronicsJournalHistory` добавляет ElectronicsJournalStreams/Changes. Student-only sync проверяет исходное участие, существующую собственную ClientId-копию и контекст назначения; не создаёт задание, не запускает код и не меняет черновик/оценку. До фиксации проверяется весь пакет дельт; принятые шаги неизменяемы, расходящееся продолжение создаёт отдельную ветвь. DatabaseHealth воспроизводит состояние и проверяет контрольные копии/родителей/связи. Teacher-only маршруты дают страницы, точный JSON шага и сверенную ссылку на отчёт.

ElectronicsHistoryStore сохраняет remote-курсор в прежнем индексе v1; старые индексы без него читаются. ElectronicsSync доставляет историю независимо от ожидающих обычных снимков, не скрывая ошибку сдачи. Native ElectronicsJournalView открывается из прежних результатов, показывает схему/код и связанный отчёт без изменения ученических данных. Для свободного отчёта без поля занятия возвращается `legacy-context`: копия/хеш сверены, занятие не угадывается. Подробности/ограничения — в native-архитектуре; D1 не меняется, роли обновляются вместе.

## Локальные переходы электроники · 5 ноября 2026

ElectronicsJournal описывает исходный JSON и упорядоченные текстовые дельты с UUID/хешами/датой/актором/видом, GestureId и необязательными ReportId/ReportHash. Replay восстанавливает и проверяет весь JSON схемы/кода на выбранном шаге. ElectronicsHistoryStore привязан к профилю/отпечатку сервера/занятию/назначению и хранит сегменты по 64 шага в соседней `.history`; index/backup фиксируются через WriteThrough/Flush/atomic rename после страниц. Обычная схема — отдельное зеркало последнего состояния, не единственный источник восстановления.

Изменения кода и жестов записываются сразу; очередь обычных снимков узнаёт о новом JSON до позднего ACK старой версии. При несовпадении зеркала проверенная история открывается с сохранением прежнего файла. Без проверенной истории повреждение не подменяется новой работой. Это пока локальный слой: серверные таблицы/API доставки этого журнала и учительский просмотр ещё не добавлены. Существующий протокол отчётов не меняется; детали/границы — в native-архитектуре.

## События процесса и связь SQL-попыток · 5 ноября 2026

SqlTextChange получил необязательный SqlJournalReference (OperationId/CodeHash либо индекс подсказки). Маркеры без изменения текста проходят тот же порядок/страницы/ACK. Remember атомарно сохраняет намерение запуска и ссылку на исходный ExecuteRequest; Acknowledge/Reject — наблюдение результата/отказа. Повтор не создаёт SQL-попытку и сохраняет старый CodeHash, даже если редактор уже изменился. Число активных секунд остаётся отдельным показателем, без записи маркера каждые две секунды.

Миграция `20261105135704_SqlJournalExecutionLinks` сохраняет OperationId в SqlExecutionEvidence для новых попыток, уникально внутри ученика; прежним строкам оставляет null. Teacher-only ссылка из шага проверяет ученика, задание, занятие, scope, вид проверки и хеш реально отправленного кода. Без соответствующего свидетельства возвращается unconfirmed/mismatch, текущая или похожая попытка не подставляется. Просмотр сохраняет исходную SQL-историю и открывает отдельную проверочную копию. Подробнее — в native-архитектуре; D1/сайт не менялись.

## Серверная доставка и просмотр SQL-журнала · 5 ноября 2026

Миграция `20261105133034_SqlJournalHistory` добавляет SqlJournalStreams и SqlJournalChanges с составными ключами ученика/потока/позиции, уникальным UUID шага, исходным/последним текстом и серверными контрольными копиями через 64 шага. Student-only `/sql-journal/sync` принимает до 64 изменений, проверяет существующую работу исходного участника, весь пакет до фиксации и не изменяет черновик/результаты/права запуска. ACK не исполняет SQL. Принятые шаги неизменяемы; восстановление расходящейся копии создаёт новый поток со ссылкой на прежний.

SqlLocalStore сохраняет квитанцию/ID ветви в прежнем v3 Work и сверяет серверную вершину после открытия. Повторно передаётся опорный принятый UUID: одинаковый итоговый SQL не скрывает другую историю правок. Teacher-only маршруты дают страницы потоков/событий и точный текст на шаге. Native SqlJournalView показывает историю отдельно от текущей работы. Подробности и пределы — в native-архитектуре. Учебный SQL остаётся только в worker; D1/сайт не меняются, роли обновляются вместе.

## Сегменты локального SQL-журнала · 5 ноября 2026

Envelope v3 сохраняет SqlJournalIndex: начальный текст, ссылки на неизменяемые блоки по 64 шага и короткий хвост. Блоки записываются/flush до атомарной замены Work-индекса. Загрузка проверяет SHA-256, контекст, StreamId, порядок и полное проигрывание. v1/v2 остаются читаемыми, перенос не удаляет исходные сегменты или backup. Подробности — в native-архитектуре. Серверная модель/протокол не меняются, доставка журнала остаётся следующим этапом.

## Первый слой E07: воспроизводимая SQL-история · 5 ноября 2026

SqlTextJournal в Contracts описывает начальный текст и упорядоченные замены фрагментов с UUID/временем клиента/actor/kind и BeforeHash/AfterHash. SqlLocalStore связывает его с имеющимися профилем/занятием/работой, фиксирует вместе с кодом и проверяет при загрузке. Файл с журналом имеет Envelope v2; v1 остаётся читаемым, отсутствующее прошлое не реконструируется. Это пока локальный слой, не полный аудит и не серверная статистика; доставка/ACK и учительский просмотр ещё открыты. Подробные ограничения — в native-архитектуре.

## Явное восстановление локальной SQL-работы · 5 ноября 2026

SqlLocalRecoveryException передаёт MainWindow проверенные сведения для экрана восстановления. RestoreBackup под профильным file lease проверяет исходный/резервный хеши, контекст и владельца, сохраняет повреждённый оригинал, готовит новую атомарную запись и оставляет backup. Код ставится в Dirty, прежний pending-save заменяется новым CAS-сохранением; UUID SQL-исполнения/событий не меняются. Поэтому восстановленная предыдущая версия не теряется при последующем Observe и не перезаписывает более новый серверный текст без сравнения. Подробности — в native-архитектуре; серверная модель/миграции не меняются.

## Долговечная SQL-очередь ученика · 5 ноября 2026

`SqlLocalStore` хранит отдельные учебные записи в пользовательском каталоге, атомарно фиксируя SQL до сетевого запроса. Ключ включает сервер/профиль, занятие, WorkScope и задание; в файле нет API-клиента/паролей/токенов/teacher-only данных. Client хранит идентичность вошедшего профиля только в памяти. Доставка проверяет её до каждого запроса; смена ученика или отпечатка не переносит очередь в чужой профиль.

Новые `/sql-sync/draft`, `/action`, `/receipt` работают с существующими Assignments/LessonSqlWorks и квитанциями Operations. Черновик использует сравнение хеша исходного текста; конфликт не перезаписывает сервер автоматически. Повтор UUID возвращает квитанцию, смена payload с тем же UUID запрещена. Сохранение старой пары проверяет исходное участие, но не даёт права исполнения; старые execute-маршруты и их ограничения сохранены. Подробности и границы — в [native-архитектуре](../avalonia/docs/architecture.md). Новых таблиц/миграций и изменений D1 нет.

## Совместная область схемы и кода · 5 ноября 2026

Native ElectronicsScreen использует разделённое по вертикали поле: схема сверху, код/монитор снизу, регулируемая граница и сворачиваемые панели. Обычные работы и точная проверочная копия используют один компонент. Управление панелями относится к состоянию просмотра, не изменяет CircuitProject/учебную статистику; при закрытии экрана прежнее сохранение/синхронизация остаются обязательными. Архитектура хранения и миграции не меняются. Подробнее — [native-архитектура](../avalonia/docs/architecture.md).

## Изоляция native-компилятора электроники · 5 ноября 2026

`FirmwareRunner.Compile` больше не запускает Arduino CLI с обычными правами приложения. `CompilerRuntime` копирует только публичные CLI/пакеты/библиотеки и `sandbox-avr` в отдельный версионный кэш; учебные проекты и метаданные туда не копируются. `WindowsSandboxProcess` создаёт уникальный AppContainer с возможностью только чтения этого комплекта и правом записи собственной временной папки. Среда собирается заново; сетевые capabilities отсутствуют. Std handles передаются явным списком, процесс создаётся suspended и включается в Windows job до продолжения. Отмена/60 секунд/выход host завершают дочерние процессы. Подробные лимиты, восстановление ресурсов и состав комплекта — в [native-архитектуре](../avalonia/docs/architecture.md).

Это ограничивает также `#include` и assembler `.incbin` из ученического кода; серверная SQLite/ученические данные не являются входами компилятора. Скрипты сборки включают автономный комплект v3 и новые x64 инструменты. Схема хранения приложения не меняется; основная рабочая установка не обновлена. Приёмка на Windows 10, реальные LAN/offline-сценарии всего приложения и матрица Cirkit остаются открытыми.

## Воспроизводимое состояние SQL-попытки · 5 ноября 2026

Worker по CaptureState возвращает BeforeSnapshot до выполнения кода, включая обычную SQL-ошибку. EvidenceVersion=1 подтверждает поддержку; сервер отвергает прежний worker с требованием совместного обновления. При тайм-ауте можно сохранить уже известный исходный проектный снимок; если его нет, состояние явно недоступно. Непустые run и check сохраняются атомарно с Attempt/Operation и результатом ученика. Повтор OperationId возвращает прежний ответ, не создавая новое свидетельство.

Миграция `20261104222327_SqlExecutionEvidence`: SqlExecutionStates (StudentId/SHA-256, канонический Base64) и SqlExecutionEvidence (AttemptId, владелец, TaskJson/редакция, Check, BeforeHash, ResultJson). Содержимое одинаковых баз переиспользуется только внутри ученика; профиль каскадно удаляет попытки, свидетельства и состояния. Health проверяет хеш/SQLite, владельца, исходное задание, действие и форму результата. Прежние данные не заполняются догадками.

Teacher-only `/teacher/sql-review/attempts/{id}` возвращает закреплённые сведения и оригинальный результат. `/execute` принимает только SQL; задание/снимок берутся из сохранённого свидетельства. Каждый запуск создаёт свою копию в отдельном worker и не вызывает ServerState.Execute, не пишет учебную статистику и не продвигает проектные снимки. Действуют его SQLite authorizer, отключённые расширения/ATTACH, очередь 4/39, 5 секунд и Windows job/лимиты памяти. Отмена HTTP передаётся worker. Исходный и проверочный результаты разделены в нативном SqlAttemptReviewView; возврат сохраняет прежнюю страницу/прокрутку.

Старая попытка без свидетельства не получает новое условие/редакцию или результат из текущего каталога. Без BeforeHash запуск недоступен. Встраивание в новые результаты занятия остаётся E10; подробные правки/действия — E07. Схема D1 и учебные материалы не менялись.

## Ограниченная проверка на ПК ученика · 4 ноября 2026

`ReviewAccessRegistry` хранит только в памяти хеши случайных кодов/допусков, цель, инициирующий teacher-сеанс и ученический сеанс. Код — 12 цифр, 5 минут, однократное потребление; допуск — 256 случайных бит, 15 минут. Авторизация проверяет текущие student-bearer и отдельный X-Review-Token, владельца/сеанс, срок и живой teacher-сеанс. Основные teacher-endpoints продолжают требовать teacher-role. Пять неверных кодов ограничивают ученика на минуту, redemption дополнительно использует сетевой rate limiter.

Выдача нового кода отзывает прошлые коды/сеансы для этого ученика. `/teacher/review-access/{id}` отзывает код и сеанс; завершение удаляет допуск. Восстановление БД очищает реестр, перезапуск создаёт новый. Ученический отдельный ClassroomApi-клиент копирует обычный student-bearer и добавляет только временный заголовок; исходный API не меняет роль или токен. Секреты не сохраняются на диске. Если сеть недоступна при выходе, локальный режим закрывается сразу, отзыв ограничен 2 секундами, а серверная проверка срока/обычных сеансов остаётся обязательной.

`/review-access/electronics` возвращает только ожидающие работы цели. Деталь доступна для ожидающего либо уже открытого в этом режиме отчёта, всегда с проверкой StudentId. ## Подробная статистика Avalonia · 19 октября 2026

LearningHistory расширяет Assignments полями StartedAt, LastActivityAt, LastHeartbeatAt, TrackingVersion, AcceptedCode и ActiveSecondsAtCompletion; Attempts — Action, Code и Explanation, с индексом student/task/time. Миграция добавляется к прежним без их изменения; автоматическая копия выполняется до применения. Не затрагивает D1, сайт и Electron.

GET teacher/learning возвращает преподавателю метаданные без SQL: группы, профили со стабильными ID и доступным каждому набором задач, статистику сохранённых назначений. GET teacher/learning/{studentId}/{taskId}?offset=N возвращает закреплённое условие/вариант, черновик, первый принятый ответ и до 100 событий с HasMore/NextOffset. История объединяет Attempts, первое открытие и первые открытия подсказок. Оба API проверяют роль на сервере. Старый overview сохранён для совместимости.

Общее время на экране — абсолютные timestamps сервера в UTC milliseconds, выводимые в локальном времени компьютера преподавателя. StartedAt фиксируется при первом явном открытии нового назначения, а не при опросе или выдаче проектной цепочки. Для старых назначений неизвестное начало не придумывается. Принятый SQL/дата/активные секунды фиксируются вместе с первым успехом в транзакции execute; новый черновик и повторные решения их не заменяют. История хранит точный SQL и ошибку отдельно от объяснения. Пустой автоматический preview не становится запуском ученика в журнале.

Активность оценивается при активном окне, незавершённом задании и отсутствии блокировки; после двух минут без клавиш, нажатий мыши или прокрутки перестаёт начисляться. Сервер ограничивает секунды фактически прошедшим временем, максимум 30 за запрос; последовательность в одной клиентской сессии предотвращает повторное начисление, включая задержавшийся старый запрос. Operations хранит одну квитанцию активности на сессию, не одну запись каждые две секунды. Это оценка взаимодействия, не измерение внимания; прежние секунды не пересчитываются.

POST tasks/{id}/events принимает UUID и opened/copy/cut/paste/clipboard/drop/capture. Идемпотентная квитанция и изменение состояния сохраняются вместе; другой payload с тем же UUID отклоняется. Clipboard/capture логируются только при Restricted; capture не вызывает паузу. Доставка событий при обрыве повторяется в памяти открытого окна; постоянная офлайн-очередь пока отсутствует.

## Самостоятельное направление Avalonia

Новое решение `avalonia/` использует .NET 10 / Avalonia 11. Учебный SQL в этом направлении выполняется на преподавательском компьютере в отдельном worker с in-memory SQLite, а не в D1. HTTPS и pinning, реляционное хранение EF Core, immutable назначения/цепочки, атомарная completion+snapshot+operation, импорт Electron, резервные копии и UI описаны в [avalonia/docs/architecture.md](../avalonia/docs/architecture.md). Ученическая поставка не включает серверные модули и каталог решений. Правила browser sql.js ниже относятся к прежнему сайту.

Сборка использует SDK 10.0.401 и locked restore. Криптографические build-зависимости Xml/Pkcs закреплены в lock-файлах на 10.0.13 для устранения NU1902/NU1903; аудит NuGet и ошибки на предупреждениях остаются включёнными. При восстановлении личного архива на новом ПК `CLASSROOM_DATA` задаётся абсолютным путём к перенесённой `avalonia/.classroom-data`, иначе Teacher откроет стандартный каталог Windows с другой базой.

Ограничения применяются только к отмеченным заданиям. Помимо клавиш окно фильтрует clipboard-события TextBox, а SQL-редактор перехватывает команды Copy/Cut/Paste до стандартных обработчиков. `SaveVariantRequest.Restricted` — необязательное поле: если задано, политика и альтернативный вариант сохраняются атомарно; если отсутствует, политика сохраняется прежней. Windows affinity проверяется после установки. Подробности проверки и оставшиеся пробелы: [аудит 19 октября](../avalonia/docs/functionality-audit-2026-10-19.md).

StudentScreen отображает состояние политики постоянно. Violation сначала синхронно выводит локальное пояснение, затем отправляет нарушение серверу, поэтому запрет понятен и при задержке/ошибке сети. Снятие Restricted очищает устаревшее сообщение. Обрабатываются события клавиш снимка, если они дошли до окна; глобальное Win+Shift+S может перехватить сама ОС. Постоянное предупреждение и Windows display affinity не зависят от получения такого KeyDown.

## Учебная база и проверка

Для самостоятельного упражнения создаются две отдельные базы из seed: фактическая и эталонная. Запрос ученика сравнивается с результатом solution по именам столбцов и значениям строк; порядок учитывается только при ordered. Для mode=state сравниваются таблицы, столбцы, записи, индексы, внешние ключи, представления и триггеры. Отдельные проверки есть для транзакции и ограничений.

Проекты используют последний SQLite-снимок успешного шага. Выполнение без проверки не изменяет сохранённый проект. После успешного state шага экспортируется файл SQLite в base64. Все шаги проекта должны использовать одну совместимую схему.

Большие seedProfile загружаются через GET /api/app?seedProfile=… по необходимости. tableMap применяется к seed, затем prepareVariantDatabase меняет числовые поля. После восстановления снимка эти преобразования повторно не выполняются.

## Варианты

Базовая версия имеет номер 1, автоматически подготовленные альтернативы — 2, 3, 4. Имена таблиц/представлений/индексов/триггеров получают суффиксы _v2…_v4. variantSql сохраняет строковые литералы и комментарии. Числовые age/amount/price/daily_rate/quantity/prize/debt/paid_amount масштабируются с округлением; идентификаторы и внешние ключи остаются прежними. Часть задач имеет отдельно заданные варианты условий. Условия остальных задач сохраняют исходную учебную цель.

Назначение: хеш task.id (или project для последовательного проекта) плюс порядковая позиция регистрации ученика в группе, modulo 4. Четыре последовательных входа новых профилей получают все четыре номера. Это распределение по регистрации, не по физическому месту в классе; после удаления профилей возможны повторы позиции.

Полный JSON назначенного Task сохраняется в learner_task_variants с ключом (learner_id, task_id), а не пересчитывается каждый раз. INSERT OR IGNORE и последующее чтение защищают от разных ответов при параллельном первом входе. Каталог и варианты, изменённые преподавателем, влияют на новые назначения. При добавлении шага к существующему проекту используется номер уже выданных шагов.

teacher_task_variants.variant_index — исторический индекс альтернативы: 1…3 соответствует видимым версиям 2…4. Старый индекс 4 не используется для новых назначений, но сохраняется для восстановления исторических проектов. Старые проектные снимки без новых назначений продолжают прежнюю схему через legacy-task-variants; это исключение из новой схемы четырёх версий.

## Безопасность и практические ограничения

Учебный SQL никогда не отправляется на исполнение в D1. SQLite-файлы учеников изолированы. Серверные операции используют связанные параметры и роль сессии. Кабинет преподавателя требует ADMIN_PASSWORD_HASH; скрытая ссылка в настройках является только UX, не контролем доступа.

Идентификация по коду + псевдониму слабая. Эталонные ответы и проверка находятся в браузере; ученик способен подделать прогресс. Ошибки и активное время также приходят от клиента. Для экзаменов потребуются отдельная аутентификация и серверная проверка в изолированной учебной базе. Не обещать абсолютную защиту от списывания.

## Desktop: отдельный прототип (ветка codex/desktop)

Сайт продолжает прежнюю архитектуру. desktop/package.json и его lockfile/зависимости независимы. desktop/build.mjs собирает server.ts и sql-worker.ts вместе с общим каталогом. Студенческая конфигурация electron-builder включает только main/preload/UI: сервер, каталог, WASM и эталоны исключены. Состав Mac arm64 Student проверен в app.asar: только main/preload/UI/manifest. Windows ещё требует проверки. Worker собирается с включённым sql.js и распаковывается вместе с WASM в app.asar.unpacked для запуска из реального пути.

Teacher запускает HTTP-сервер только на 127.0.0.1:47831. Desktop renderer использует узкий IPC через sandboxed preload; токен остаётся в main, роль и маршруты проверяются в IPC и на сервере. Student запускает собственный локальный UI без удалённой навигации, не принимает роль teacher. Учебные запросы выполняются sql.js внутри worker_threads, отдельно от базы метаданных; четыре одновременно, до пяти секунд каждый. Это защита от зависания, не полноценная изоляция процессов по памяти.

SQLite метаданных хранит JSON состояния в одной строке; запись — экспорт в временный файл с rename. В профиле сохраняются scrypt-хеш, неизменяемое назначение Task, прогресс и успешные снимки проектов. Сервер хранит роли и сессии в памяти: после перезапуска нужен повторный вход. Сессия до восьми часов. Эталонный SQL, seed и снимки не возвращаются ученику. Результат признаётся только сервером, клиентский completed игнорируется.

Редактирование преподавателем увеличивает revision. Опрос каждые две секунды доставляет изменения настроек. Открытые задания и все шаги начатого проекта сохраняют прежнее условие; новые назначения используют новые данные. Restriction переключается для задания независимо от назначения. Для обновления уже начатых работ нужен отдельный интерфейс явного переназначения с резервной копией.

В обычных упражнениях clipboard разрешён. В отмеченных преподавателем заданиях блокируются copy/cut/paste, альтернативные сочетания Insert/Delete и drag/drop в UI. Electron перехватывает сочетания в своём окне; clipboard-события передаются через IPC. Пауза проверяется сервером и отображается в UI, преподаватель может снять её. Отсутствие события от модифицированного клиента не доказывает отсутствие копирования. Защита экрана использует setContentProtection. Win+Shift+S проверен в Windows 11/Parallels: Student исключается из снимка, показывается фон/окно позади. Попытка скриншота не вызывает паузу. Механизм не определяет все попытки скриншота и не защищает от фотографии.

Не открывать HTTP-прототип на 0.0.0.0: перед LAN нужны HTTPS, первичное сопряжение и проверка сертификата. Перенос сайтовой D1 и старых гостевых профилей не реализован. Установщики пока тестовые, без подписи, не предназначены для контрольной в реальном классе.

### Учёт подсказок desktop

В JSON состояния SQLite профиль ученика содержит hints: taskId → массив серверных timestamps, по порядку task.hints. Старый профиль без hints читается как пустой. POST /api/hint принимает taskId и индекс с нуля от текущего ученика. Следующий индекс сохраняется атомарным persist; пропуск, нецелый или отсутствующий индекс отклоняется, повтор уже открытого индекса идемпотентен. На паузе открытия запрещены. GET/POST /api/task возвращает hintUsage (count, total, openedAt) отдельно от назначения; total берётся из закреплённого варианта. Electron разрешает новый маршрут ученику через существующий IPC.

Teacher overview возвращает hintUsage по каждому ученику и заданию с названием/номером закреплённого варианта; пароли и снимки не включены. UI обновляет только отчёты раз в пять секунд, сохраняя поля редактора. Это журнал действий штатного интерфейса: наличие записи не доказывает прочтение текста, а отсутствие не исключает просмотр подсказки вне кнопки.

### Оформление desktop

POST /api/theme сохраняет theme в текущем профиле ученика или teacherTheme в состоянии преподавателя. Тело: {theme:{preset,colors?}}, preset один из light/mist/paper/dark/onyx/midnight, colors — только background/surface/accent/editor в формате #RRGGBB. Цвета нормализуются в верхний регистр; неизвестные ключи отклоняются. Запрос не принимает ID другого ученика. Login возвращает серверное предпочтение; старый профиль без темы получает light. Настройки не меняют каталог, варианты, подсказки или прогресс.

Общий desktop/ui/themes.js хранит заготовки, строит производные цвета и выставляет CSS-переменные. В index.html он подключён перед app.js; browser-server разрешает этот статический файл, Electron копирует вместе с UI. Выбор без сохранения — временный предпросмотр; отмена возвращает серверное предпочтение. Окно настроек доступно с клавиатуры и закрывается Escape. Серверная тема является источником восстановления; локальная запись используется только как вспомогательное отражение предпочтения.

### Личные темы desktop

В состоянии ученика хранится `themePresets`, преподавателя — `teacherThemePresets`: массив `{id,name,theme}`. Авторизованный POST `/api/theme-presets` принимает `action: save` с названием и проверенной темой либо `action: delete` с ID. Сервер выбирает владельца по сессии; указать чужой профиль невозможно. Название до 50 символов, до 30 тем, повторяющиеся названия запрещены без учёта регистра. Вход возвращает `themePresets` вместе с активной темой. Сохранение пресета не меняет активную тему; применение выполняется прежним `/api/theme`.

Новая пустая схема содержит только пустые setup() и loop(); пример Blink сохраняет собственную программу. Добавление компонента не вставляет код автоматически.
