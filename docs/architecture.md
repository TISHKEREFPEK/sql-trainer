# Архитектура

## Самостоятельное направление Avalonia

Новое решение `avalonia/` использует .NET 10 / Avalonia 11. Учебный SQL в этом направлении выполняется на преподавательском компьютере в отдельном worker с in-memory SQLite, а не в D1. HTTPS и pinning, реляционное хранение EF Core, immutable назначения/цепочки, атомарная completion+snapshot+operation, импорт Electron, резервные копии и UI описаны в [avalonia/docs/architecture.md](../avalonia/docs/architecture.md). Ученическая поставка не включает серверные модули и каталог решений. Правила browser sql.js ниже относятся к прежнему сайту.

## Учебная база и проверка

Для самостоятельного упражнения создаются две отдельные базы из seed: фактическая и эталонная. Запрос ученика сравнивается с результатом solution по именам столбцов и значениям строк; порядок учитывается только при ordered. Для mode=state сравниваются таблицы, столбцы, записи, индексы, внешние ключи, представления и триггеры. Отдельные проверки есть для транзакции и ограничений.

Проекты используют последний SQLite-снимок успешного шага. Выполнение без проверки не изменяет сохранённый проект. После успешного state шага экспортируется файл SQLite в base64. Все шаги проекта должны использовать одну совместимую схему.

Большие seedProfile загружаются через GET /api/app?seedProfile=… по необходимости. tableMap применяется к seed, затем prepareVariantDatabase меняет числовые поля. После восстановления снимка эти преобразования повторно не выполняются.

## Варианты

Базовая версия имеет номер 1, автоматически подготовленные альтернативы — 2, 3, 4. Имена таблиц/представлений/индексов/триггеров получают суффиксы _v2…_v4. variantSql сохраняет строковые литералы и комментарии. Числовые age/amount/price/daily_rate/quantity/prize/debt/paid_amount масштабируются с округлением; идентификаторы и внешние ключи остаются прежними. Часть задач имеет отдельно заданные варианты условий. Условия остальных задач сохраняют исходную учебную цель.

Назначение: хеш task.id (или project для последовательного проекта) плюс порядковая позиция регистрации ученика в группе, modulo 4. Четыре последовательных входа новых профилей получают все четыре номера. Это распределение по регистрации, не по физическому месту в классе; после удаления профилей возможны повторы позиции.

Полный JSON назначенного Task сохраняется в learner_task_variants с ключом (learner_id, task_id), а не пересчитывается каждый раз. INSERT OR IGNORE и последующее чтение защищают от разных ответов при параллельном первом входе. Каталог и варианты, изменённые преподавателем, влияют на новые назначения. При добавлении шага к существующему проекту используется номер уже выданных шагов.

teacher_task_variants.variant_index — исторический индекс альтернативы: 1…3 соответствует видимым версиям 2…4. Старый индекс 4 не используется для новых назначений, но сохраняется для восстановления исторических проектов. Старые проектные снимки без новых назначений продолжают прежнюю схему через legacy-task-variants; это исключение из новой схемы четырёх версий.

## Хранение

| Таблица D1 | Содержимое |
|---|---|
| groups | Группы и коды |
| learners | Псевдоним, завершённые задания, снимки проектов |
| sessions | Хеш токена, роль, срок действия |
| attempts | Сообщения об ошибках |
| teacher_tasks | Изменённые/добавленные задания и отметки удаления |
| teacher_task_variants | Правки альтернатив преподавателем |
| learner_task_stats | Начало, активные секунды, проверки, ошибки, завершение |
| learner_task_variants | Зафиксированные задания профиля |

Гости: IndexedDB и localStorage; черновики редактора локальные также у вошедшего ученика. Студенты: прогресс и проекты в D1, доступ на другом устройстве после входа с теми же кодом и псевдонимом. Cookie sql_session — HttpOnly, Secure, SameSite=Lax. POST проверяет Origin.

Перенос гостя объединяет выполненные задания. Для отсутствующих серверных проектов переименовывает таблицы из гостевого снимка согласно tableMap назначенного проекта, сохраняя данные и связи. Уже существующие серверные проекты не заменяются. Ошибка переноса остаётся видимой, гостевой оригинал сохраняется.

## Безопасность и практические ограничения

Учебный SQL никогда не отправляется на исполнение в D1. SQLite-файлы учеников изолированы. Серверные операции используют связанные параметры и роль сессии. Кабинет преподавателя требует ADMIN_PASSWORD_HASH; скрытая ссылка в настройках является только UX, не контролем доступа.

Идентификация по коду + псевдониму слабая. Эталонные ответы и проверка находятся в браузере; ученик способен подделать прогресс. Ошибки и активное время также приходят от клиента. Для экзаменов потребуются отдельная аутентификация и серверная проверка в изолированной учебной базе. Не обещать абсолютную защиту от списывания.

## Обновления

Новая таблица назначений вводится миграцией 0003. Для Sites архив содержит drizzle в dist/.openai/drizzle: публикация должна применить отсутствующие миграции к целевой D1 до размещения нового кода. После публикации сверить схему через database overview. Для другого хостинга миграции применять отдельно. Локальная .wrangler/state и hosted D1 независимы. Клонирование GitHub не переносит локальную базу, секреты или историю чата. Публикация Sites — отдельное явно разрешаемое действие.

## Desktop: отдельный прототип (ветка codex/desktop)

Сайт продолжает прежнюю архитектуру. desktop/package.json и его lockfile/зависимости независимы. desktop/build.mjs собирает server.ts и sql-worker.ts вместе с общим каталогом. Студенческая конфигурация electron-builder включает только main/preload/UI: сервер, каталог, WASM и эталоны исключены. Состав Mac arm64 Student проверен в app.asar: только main/preload/UI/manifest. Windows ещё требует проверки. Worker собирается с включённым sql.js и распаковывается вместе с WASM в app.asar.unpacked для запуска из реального пути.

Teacher запускает HTTP-сервер только на 127.0.0.1:47831. Desktop renderer использует узкий IPC через sandboxed preload; токен остаётся в main, роль и маршруты проверяются в IPC и на сервере. Student запускает собственный локальный UI без удалённой навигации, не принимает роль teacher. Учебные запросы выполняются sql.js внутри worker_threads, отдельно от базы метаданных; четыре одновременно, до пяти секунд каждый. Это защита от зависания, не полноценная изоляция процессов по памяти.

SQLite метаданных хранит JSON состояния в одной строке; запись — экспорт в временный файл с rename. В профиле сохраняются scrypt-хеш, неизменяемое назначение Task, прогресс и успешные снимки проектов. Сервер хранит роли и сессии в памяти: после перезапуска нужен повторный вход. Сессия до восьми часов. Эталонный SQL, seed и снимки не возвращаются ученику. Результат признаётся только сервером, клиентский completed игнорируется.

Редактирование преподавателем увеличивает revision. Опрос каждые две секунды доставляет изменения настроек. Открытые задания и все шаги начатого проекта сохраняют прежнее условие; новые назначения используют новые данные. Restriction переключается для задания независимо от назначения. Для обновления уже начатых работ нужен отдельный интерфейс явного переназначения с резервной копией.

В обычных упражнениях clipboard разрешён. В отмеченных преподавателем заданиях блокируются copy/cut/paste, альтернативные сочетания Insert/Delete и drag/drop в UI. Electron перехватывает сочетания в своём окне; clipboard-события передаются через IPC. Пауза проверяется сервером и отображается в UI, преподаватель может снять её. Отсутствие события от модифицированного клиента не доказывает отсутствие копирования. Защита экрана использует setContentProtection. Win+Shift+S проверен в Windows 11/Parallels: Student исключается из снимка, показывается фон/окно позади. Попытка скриншота не вызывает паузу. Механизм не определяет все попытки скриншота и не защищает от фотографии.

Не открывать HTTP-прототип на 0.0.0.0: перед LAN нужны HTTPS, первичное сопряжение и проверка сертификата. Перенос сайтовой D1 и старых гостевых профилей не реализован. Установщики пока тестовые, без подписи, не предназначены для контрольной в реальном классе.

### Разделение browser storage desktop

Teacher и Student получают отдельные постоянные session partitions: persist:classroom-teacher и persist:classroom-student. Перед закрытием UI сохраняет черновик; при завершении вызывается flushStorageData. Это отделяет localStorage ролей при одинаковом package.name и совместном запуске; путь SQLite преподавателя сохраняется. Старый default-partition автоматически не мигрирует. Правка проверена в установленной Windows-сборке 0.1.1: новый черновик восстановлен после полного закрытия и повторного входа. Заголовок окна закреплён за ролью, чтобы HTML title не скрывал различие приложений.

### Компоновка desktop 0.1.2

UI остаётся общим для обоих установщиков (desktop/ui). Списки создаются поверх скрытых select и вызывают их change, не меняя IPC/API. На широком окне рабочие области используют доступную высоту: прокрутка внутри длинной карточки/формы/результата, на узком окне — прокрутка документа. Полный аудит незавершённых desktop-функций: docs/desktop-review.md.

### Учёт подсказок desktop

В JSON состояния SQLite профиль ученика содержит hints: taskId → массив серверных timestamps, по порядку task.hints. Старый профиль без hints читается как пустой. POST /api/hint принимает taskId и индекс с нуля от текущего ученика. Следующий индекс сохраняется атомарным persist; пропуск, нецелый или отсутствующий индекс отклоняется, повтор уже открытого индекса идемпотентен. На паузе открытия запрещены. GET/POST /api/task возвращает hintUsage (count, total, openedAt) отдельно от назначения; total берётся из закреплённого варианта. Electron разрешает новый маршрут ученику через существующий IPC.

Teacher overview возвращает hintUsage по каждому ученику и заданию с названием/номером закреплённого варианта; пароли и снимки не включены. UI обновляет только отчёты раз в пять секунд, сохраняя поля редактора. Это журнал действий штатного интерфейса: наличие записи не доказывает прочтение текста, а отсутствие не исключает просмотр подсказки вне кнопки.

### Оформление desktop

POST /api/theme сохраняет theme в текущем профиле ученика или teacherTheme в состоянии преподавателя. Тело: {theme:{preset,colors?}}, preset один из light/mist/paper/dark/onyx/midnight, colors — только background/surface/accent/editor в формате #RRGGBB. Цвета нормализуются в верхний регистр; неизвестные ключи отклоняются. Запрос не принимает ID другого ученика. Login возвращает серверное предпочтение; старый профиль без темы получает light. Настройки не меняют каталог, варианты, подсказки или прогресс.

Общий desktop/ui/themes.js хранит заготовки, строит производные цвета и выставляет CSS-переменные. В index.html он подключён перед app.js; browser-server разрешает этот статический файл, Electron копирует вместе с UI. Выбор без сохранения — временный предпросмотр; отмена возвращает серверное предпочтение. Окно настроек доступно с клавиатуры и закрывается Escape. Серверная тема является источником восстановления; локальная запись используется только как вспомогательное отражение предпочтения.

### Личные темы desktop

В состоянии ученика хранится `themePresets`, преподавателя — `teacherThemePresets`: массив `{id,name,theme}`. Авторизованный POST `/api/theme-presets` принимает `action: save` с названием и проверенной темой либо `action: delete` с ID. Сервер выбирает владельца по сессии; указать чужой профиль невозможно. Название до 50 символов, до 30 тем, повторяющиеся названия запрещены без учёта регистра. Вход возвращает `themePresets` вместе с активной темой. Сохранение пресета не меняет активную тему; применение выполняется прежним `/api/theme`.
