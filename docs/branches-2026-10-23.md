## Предложение упрощения

Оставить три понятные линии: **main** — сайт, **codex/desktop** — прежний Electron, **codex/avalonia-classroom** — актуальное новое приложение. Короткие задачи создавать от соответствующей линии и убирать после включения.

Для этого после решения владельца можно:

1. Перенаправить PR #7 прямо в codex/avalonia-classroom. Все четыре содержательных коммита #4–#7 войдут в один diff. Повторить проверки актуального PR.
2. Объединить #7 с сохранением истории (merge commit), затем убедиться, что прежняя вершина full-functionality-bugfix содержится в avalonia-classroom. Закрыть #4–#6 как заменённые общим PR, если GitHub не отметил их автоматически.
3. Только после этого удалить временные windows-transfer-setup, functionality-audit, restriction-feedback и full-functionality-bugfix; исправить ссылки на ветку в инструкции передачи. Для контрольной точки при необходимости сохранить tag. Не удалять базовые ветки открытых PR до перенаправления/закрытия.
4. Две уже merged сайтовые ветки можно удалить независимо от объединения Avalonia.

PR #3 сейчас предлагает включить Avalonia в старую Electron-ветку. Для независимых линий его не нужно автоматически объединять: можно оставить для сравнения или закрыть с пояснением после выбора стратегии. В main новое направление этим планом не вливается, Sites не публикуется.
