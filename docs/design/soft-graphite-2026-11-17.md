## Утверждённый объём и границы

Подробно заданы общий стиль, SQL-экран ученика и «Моё занятие». Преподавательский эскиз задаёт общее оформление, а не новую структуру функций. Сохраняются пять основных разделов преподавателя и постоянно доступная очередь проверки. Для электроники сохраняется ранее выбранный код под схемой; отдельный новый макет редактора и детальной статистики этим документом не утверждается.

Все экраны используют реальные назначения, данные, состояния и команды. Иллюстративные книги, ФИО, группа и счётчики не становятся данными приложения. Не переносить имитацию SQL/сохранения из HTML. Учебный SQL остаётся в изолированном native SQLite worker. Политики входа, пауз, направлений, ограничений, зачёта и пересдач не меняются.

Найденные при сопоставлении места: текущий `light` имеет фиолетовый акцент и тёмный редактор; SQL содержит MinHeight 230/580, общий ScrollViewer и старое соотношение колонок; справочник использует `ShowPage`. Это точки изменения, а не основание переписывать сервер или модель курса. Проверить также универсальный MaxHeight таблицы: SQL-результат должен занимать выделенную область.

Действия Undo/Redo используют существующий TextCommand и настоящий UndoStack. «Сбросить» возвращает только `current.Starter`. Один справочник открывается диалогом, Escape закрывает его с возвратом фокуса, не создавая новый редактор. Run/Check используют прежние `Execute(false/true)` и CanExecute. Сохраняются UUID исходного выполнения, generation, LessonId/WorkScope, SQL первоначального запроса и семантика разрешённого повтора. Поздний ответ не попадает в другое задание.

Критический статус сохранения нельзя скрыть только в tooltip, даже на 704×396. Подробности можно раскрыть отдельной панелью, основные команды остаются видимыми. Общий таймер сохранения из эскиза не используется; успешная локальная запись не означает ACK преподавателя. Изменение SQL не отменяет прежний зачёт.
