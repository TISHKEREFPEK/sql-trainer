## Последний WIP: где остановились

Добавлены `Classroom.Storage/ElectronicsProjectEntity.cs` и `Classroom.Server/ElectronicsProjects.cs` (пути относительно `avalonia/src`). Изменены контракты `Electronics.cs`, `ClassroomDb.cs`, серверные `Routes.cs`, `ElectronicsRoutes.cs`, `ElectronicsReviews.cs`, `ElectronicsJournalRoutes.cs`.

Заложены логический ID свободного проекта, общий черновик с ревизией и отдельные снимки исходных занятий. API: список/получение собственного проекта, идемпотентное создание и открытие в активном занятии. Необязательный `ElectronicsFreeContext(ProjectId, LessonId, ExpectedRevision)` должен фиксироваться в очереди, а не выводиться из текущего входа. Старые очереди/сдачи остаются без контекста: нельзя объединять по имени или угадывать занятие.

Запись проверяет ожидаемую ревизию (конфликт двух ПК → 409 с сохранением локальных данных). Повтор возвращает ревизию принятой копии, не новую вершину другого ПК. Поздняя доставка требует исходного участия и не разрешает работу после паузы; прежний ClientId нельзя перепривязать. Новый свободный проект использует ручную сдачу/пересдачу. Исторические имена `ExpectedAssignmentVersion` / `AssignmentVersion` используются также для версии разрешения свободного проекта; `ProjectRevision` отдельно описывает содержимое.

**Не сделаны:** EF-миграция/snapshot, DatabaseHealth новых сущностей, тесты; клиентские методы/выбор проектов; долговечный FreeContext в outbox и новые имена файлов фоновой доставки; свободные схемы в общих результатах. Обычный редактор пока продолжает старый путь копии устройства. Новый API к нему не подключён.

Следующий порядок:

1. Проверить сборку/EF-связи, дополнить DatabaseHealth и создать новую миграцию. Применённые миграции не редактировать; старым данным оставить null без выдуманного контекста.
